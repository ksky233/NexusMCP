# 04｜数据模型与状态所有权

> 状态：S2 核心模型已冻结；S3/S4 模型仍为概念草案
> 原则：先定义状态所有者和事务边界，再设计 ORM；旧 MySQL 表只作为迁移输入。

## 1. 分阶段范围

### S2 首批持久化模型

```text
Tenant
UpstreamService
OpenApiImportJob
ImportedOperation
Tool
ToolVersion
ToolBinding
```

它们支持第一条闭环：

```text
注册 Upstream
→ 导入 OpenAPI
→ 生成 ImportedOperation
→ 创建 Draft ToolVersion + ToolBinding
→ Review
→ Publish
→ tools/list 可见
```

### S3/S4 后续模型

```text
Principal / Identity Mapping
ToolPolicy
CredentialBinding
ApprovalRequest
ToolExecution
AuditEvent
KnowledgeDocument / KnowledgeChunk
```

后续模型在对应用例出现前不创建空表。

## 2. 状态所有权总表

| 领域 | 拥有的核心状态 | 不拥有 |
|---|---|---|
| Identity | Tenant、Principal、Role/Claims Mapping | Upstream Secret 明文 |
| Registry | UpstreamService、Transport、Endpoint Metadata、Health | Tool Schema、Agent Session |
| OpenAPI Import | ImportJob、ImportedOperation、Normalized Schema、Review Result | Published Tool、Runtime Execution |
| Catalog | Tool、ToolVersion、Publish Lifecycle、Visibility、Search Document | Tool Credential、HTTP 执行 |
| Connectors | ToolBinding、HTTP/MCP 执行映射 | Tool 发布生命周期、Secret Value |
| Policy | Subject/Resource/Action Rule、Decision | Secret Value、HTTP 执行 |
| Credentials | SecretReference、CredentialBinding、Grant Metadata | Secret 出现在 Tool Schema |
| Approval | ApprovalRequest、Decision、Expiry、Argument Digest | Channel UI Session |
| Execution | ToolExecution、Idempotency、Outcome | 长期 Agent Memory |
| Audit | Append-only Event、Digest、Redaction Metadata | 完整敏感 Payload |
| RAG Demo | Document、Chunk、Embedding、Source | NexusMCP Tool Catalog 本体 |

## 3. S2 核心实体

### 通用责任字段

| 字段 | 含义 |
|---|---|
| `tenant_id` | 数据和权限隔离边界，表示记录属于哪个企业/Workspace；Repository 查询必须携带它。 |
| `owner` | 维护责任人或责任团队，例如 `hr-platform-team`；用于治理、检索和告警，不是权限隔离边界。 |
| `created_by` | 创建本次记录/版本/任务的 Actor，用于追溯“谁执行了该动作”，不表示长期维护责任。 |

例如：

```text
tenant_id = acme-corp
owner = hr-platform-team
created_by = user-123
```

含义分别是“属于哪个公司”“由哪个团队维护”“这次是谁创建的”。

### 3.1 Tenant

第一版只运行一个本地 Tenant，但所有核心表从第一天携带 `tenant_id` 并通过测试证明隔离。

```text
Tenant
- id
- name
- status: active | disabled
- created_at / updated_at
```

第一版不建设完整用户中心。Tenant 使用应用生成的 UUID；开发和测试通过 Fixture 创建本地 Tenant，不把环境数据写死在 Migration 中。

关键字段：

| 字段 | 含义 |
|---|---|
| `name` | Tenant 的展示名称，不承担唯一身份；程序关联始终使用 `id`。 |
| `status` | Tenant 是否允许继续使用 NexusMCP；Disabled Tenant 下的业务请求应被拒绝。 |

### 3.2 UpstreamService

Registry 同时登记 HTTP/OpenAPI 服务和 Remote MCP Server：

```text
UpstreamService
- id
- tenant_id
- namespace
- name
- description
- owner
- service_type: http | remote_mcp
- transport_type
- endpoint
- protocol_min / protocol_max（Remote MCP 可选）
- auth_scheme（非敏感描述）
- config_json（非敏感 JSONB）
- status: draft | active | disabled
- created_at / updated_at
```

关键字段：

| 字段 | 含义 |
|---|---|
| `tenant_id` | Upstream 所属的隔离范围；不同 Tenant 可以登记同名服务。 |
| `namespace` | 服务及其 Tool 的稳定分组/前缀，例如 `directory`、`ops`；用于检索、治理和避免跨来源重名。 |
| `name` | 服务自身名称，例如 `employee-directory-api`，不等于 Tool Name。 |
| `owner` | 负责维护该 Upstream 的团队或人员，不用于判断数据属于哪个 Tenant。 |
| `service_type` | 区分普通 HTTP/OpenAPI 服务与已经实现 MCP 的远端服务。 |
| `transport_type` | 实际连接方式；HTTP 服务通常为 `http`，Remote MCP 可以是 `streamable_http`、`stdio` 等。 |
| `endpoint` | 上游基础地址或连接目标；调用前必须经过 URL/网络安全校验。 |
| `protocol_min/max` | Remote MCP 声明并验证过的最小/最大 MCP Protocol Revision，例如 `2025-11-25`～`2026-07-28`；普通 HTTP 服务为空。 |
| `auth_scheme` | 只描述认证类型，例如 `bearer`、`oauth2`、`api_key`；不保存真实 Credential。 |
| `config_json` | Transport 等非敏感扩展配置；禁止保存 Token、Password、Cookie。 |
| `status` | Draft 尚不可使用；Active 可接入；Disabled 不允许继续执行 Tool。 |

规则：

- `(tenant_id, namespace, name)` 唯一；
- Endpoint 必须通过 URL/网络边界校验；
- `config_json` 不保存 Token、Password、Cookie 或完整 Authorization Header；
- 禁用 Upstream 后，其 Tool 不可调用；具体发现缓存失效在应用层处理。

### 3.3 OpenApiImportJob

一次完整导入任务，而不是一个 Parser 函数：

```text
OpenApiImportJob
- id
- tenant_id
- upstream_service_id
- source_type: upload | local_fixture | url
- source_ref
- source_digest
- openapi_version
- operation_allowlist_json
- allowlist_snapshot_json
- status: pending | validating | parsing | completed | failed
- error_summary
- created_by
- created_at / started_at / completed_at
```

关键字段：

| 字段 | 含义 |
|---|---|
| `upstream_service_id` | 本次导入属于哪个已注册 HTTP Upstream。 |
| `source_type` | 文档如何进入系统；第一版只启用 `local_fixture`。 |
| `source_ref` | 文档位置引用，例如本地 Fixture Path、Upload Object Key 或 URL；不是文档正文。 |
| `source_digest` | 原始文档内容摘要，用于重复导入判断和来源追踪。 |
| `openapi_version` | 识别出的 OpenAPI 版本，例如 `3.0.3`、`3.1.0`。 |
| `operation_allowlist_json` | 调用者明确希望导入的 Operation ID/Path 范围。 |
| `allowlist_snapshot_json` | 导入当时实际生效的 Host/Network 安全 Allowlist 快照，用于审计安全决策。 |
| `status` | 描述一次 Job 的执行阶段和最终结果。 |
| `error_summary` | 适合管理端展示的脱敏失败摘要，不保存完整敏感文档或 Stack Trace。 |
| `created_by` | 发起本次导入的 Actor。 |

第一条纵向切片只支持 `local_fixture`；远程 URL Fetch 等 SSRF 策略完成后再启用。

### 3.4 ImportedOperation

某次 ImportJob 从 OpenAPI Path/Method 中生成的标准化 Operation：

```text
ImportedOperation
- id
- tenant_id
- import_job_id
- upstream_service_id
- operation_key
- operation_id
- method
- path
- normalized_operation_json
- generated_tool_name
- conflict_status
- review_status: pending | accepted | rejected | needs_change
- review_notes
- draft_tool_version_id（可选）
- draft_tool_binding_id（可选）
- created_at / updated_at
```

关键字段：

| 字段 | 含义 |
|---|---|
| `operation_key` | NexusMCP 生成的确定性操作键，通常由 Method + Path 等标准化信息构成；用于同一 Job 内去重。 |
| `operation_id` | OpenAPI 原文中的 `operationId`；可能缺失或与其他来源冲突。 |
| `method/path` | 上游真实 HTTP Operation 的定位信息。 |
| `normalized_operation_json` | 解析 `$ref` 后的统一中间表示，包含 Path/Query/Header/Body、Schema、Security 和 Response Metadata。 |
| `generated_tool_name` | 根据 Namespace/Operation 规则生成的候选 MCP Tool Name，Review 时仍可调整。 |
| `conflict_status` | 是否存在名称冲突、缺失 Operation ID 或不支持特性。 |
| `review_status/notes` | 人工或策略审核结论及必要说明。 |
| `draft_tool_version_id` | Accepted 后生成的 Draft ToolVersion；未生成时为空。 |
| `draft_tool_binding_id` | Accepted 后生成的 Draft ToolBinding；未生成时为空。 |

规则：

- `(import_job_id, operation_key)` 唯一；
- Normalized Operation 保存参数位置、Request Body、Security Requirement 和 Response Metadata；
- ImportedOperation 不是 Published Tool；
- Rejected Operation 不得生成可发布版本；
- 相同 Source Digest 的重复导入需要明确幂等行为。

### 3.5 Tool

Tool 表示稳定身份，不保存版本化 Schema：

```text
Tool
- id
- tenant_id
- namespace
- canonical_name
- owner
- status: active | disabled
- created_at / updated_at
```

关键字段：

| 字段 | 含义 |
|---|---|
| `namespace` | Tool 的独立分组字段，例如 `directory`；便于查询和治理，不要求运行时拆分 Tool Name 字符串。 |
| `canonical_name` | 向 MCP Client 暴露的稳定完整名称，例如 `directory.get_employee`；版本升级时保持不变。 |
| `owner` | 负责维护 Tool 契约和发布流程的团队/人员。 |
| `status` | 控制整个 Tool 身份是否可用；Disabled 会覆盖 Version 的 Published 状态。 |

规则：

- `(tenant_id, canonical_name)` 唯一；
- Tool ID 在版本升级时保持稳定；
- Disable Tool 会阻止所有版本被发现和调用；
- Tool 不直接保存 HTTP URL、Secret、JSON Schema 或 Retry 配置。

### 3.6 ToolVersion

ToolVersion 保存对 Agent 暴露的不可变版本化契约：

```text
ToolVersion
- id
- tenant_id
- tool_id
- version
- display_name
- description
- input_schema_json
- output_schema_json（可选）
- schema_digest
- tags_json
- side_effect: read_only | idempotent_write | non_idempotent_write | unknown
- visibility: public | authenticated | restricted
- status: draft | review | published | retired
- created_by
- created_at / reviewed_at / published_at / retired_at
```

关键字段：

| 字段 | 含义 |
|---|---|
| `tool_id` | 所属稳定 Tool Identity；一个 Tool 可以有多个历史 Version。 |
| `version` | Tool 内单调递增的版本号，不等于项目版本或 MCP Protocol Version。 |
| `display_name` | 面向管理端/用户的展示名称；MCP 调用仍使用 Tool `canonical_name`。 |
| `input/output_schema_json` | 向 MCP Client 暴露的 JSON Schema；使用 JSONB 保存完整结构。 |
| `schema_digest` | Canonical JSON 的摘要，用于 Diff、缓存失效、重复发布检查。 |
| `tags_json` | 搜索、分类和治理标签，不决定执行地址。 |
| `side_effect` | 调用副作用分类，决定 Retry/Approval/Idempotency 策略。 |
| `visibility` | Catalog 粗粒度发现范围；`tools/call` 仍需重新执行 Policy。 |
| `status` | Draft/Review 不可发现；Published 为当前版本；Retired 只保留历史证据。 |
| `created_by` | 创建该版本的 Actor，不等于长期 Owner。 |

规则：

- `(tool_id, version)` 唯一；
- Draft/Review 版本不可出现在普通 `tools/list`；
- 一个 Tool 同时最多有一个 `published` 版本；
- 发布后的 Schema、SideEffect 和 Binding 不原地修改；变更必须创建新版本；
- 新版本发布时，旧 Published 版本进入 `retired`；
- Schema 使用 JSONB 保存，`schema_digest` 使用确定性 Canonical JSON 计算。

S2-5 Persistence Adapter 增加派生搜索快照：

```text
search_name        = namespace + canonical_name + display_name
search_tags        = tags
search_description = description
search_vector      = PostgreSQL Stored Generated tsvector
```

这些字段是 PostgreSQL FTS Adapter 的去规范化索引输入，不进入 ToolVersion Domain Entity，也不改变
Published Tool Contract。Repository 在新增/保存 Version 时同步前三个文本字段，PostgreSQL 自动生成
`search_vector`。

### 3.7 ToolBinding

ToolBinding 属于 Connectors，精确绑定一个 ToolVersion 与执行目标：

```text
ToolBinding
- id
- tenant_id
- tool_version_id
- upstream_service_id
- imported_operation_id（OpenAPI 来源时可选）
- binding_type: http | remote_mcp
- binding_config_json（非敏感 JSONB）
- binding_digest
- status: draft | published | disabled
- created_at / published_at / updated_at
```

关键字段：

| 字段 | 含义 |
|---|---|
| `tool_version_id` | 精确绑定的 ToolVersion；Binding 不跨版本复用。 |
| `upstream_service_id` | Tool 最终执行所访问的 Upstream。 |
| `imported_operation_id` | OpenAPI 来源证据；手工或 Remote MCP Binding 可以为空。 |
| `binding_type` | 选择 HTTP Executor 或 Remote MCP Proxy。 |
| `binding_config_json` | 非敏感执行映射，例如 Method、Path Template、参数位置、Timeout/Response Policy。 |
| `binding_digest` | Binding 配置摘要，用于发布校验、Diff 和篡改检测。 |
| `status` | Draft 尚不可执行；Published 与 ToolVersion 同事务发布；Disabled 不允许执行。 |

HTTP Binding Config 可以表达：

```text
method
path_template
path/query/header/body parameter mapping
content_type
timeout policy
response content-type/size policy
```

Remote MCP Binding Config 可以表达：

```text
remote_tool_name
protocol/version requirement
timeout policy
```

规则：

- 第一版每个 ToolVersion 恰好一个 Binding；
- ToolBinding 必须与 ToolVersion、Upstream 属于同一 Tenant；
- Binding 不保存 Secret Value，只引用后续 CredentialBinding；
- Published ToolVersion 必须拥有 Published Binding；
- Binding 内容变化必须产生新 ToolVersion/Binding，不修改历史发布记录。

## 4. S3 概念模型

### 4.1 Principal

```text
Principal
- id
- tenant_id
- type: user | service | agent
- external_subject
- display_name
- status
```

### 4.2 ToolPolicy

```text
ToolPolicy
- id
- tenant_id
- subject_type / subject_id
- resource_type / resource_id
- action
- effect: allow | deny | require_approval
- condition_json
- priority
- status
- version
```

默认 Decision 推荐 `DENY`。第一版不引入通用 Rego/Cedar Engine。

### 4.3 CredentialBinding

```text
CredentialBinding
- id
- tenant_id
- tool_id / upstream_service_id
- principal_scope / role_scope
- provider
- secret_ref
- grant_type: user | service
- scopes
- status
- expires_at（Metadata）
```

只保存 SecretReference，Audit 只记录 Binding ID。

### 4.4 ApprovalRequest

```text
ApprovalRequest
- id
- tenant_id
- principal_id
- tool_id
- tool_version_id
- arguments_digest
- status: pending | approved | rejected | expired | consumed
- policy_version
- idempotency_key
- requested_at
- expires_at
- decided_by / decided_at
- consumed_at
```

S3-4 首版只持久化调用摘要，不持久化完整 Arguments。MRTR 的 `requestState` 由协议边界加密保护并由
Host 保存，不写入 Approval 表。面向异步审批人的安全参数预览仍是后续 Control Plane UX 议题。

### 4.5 ToolExecution

```text
ToolExecution
- id
- tenant_id
- request_id / trace_id
- principal_id
- tool_id / tool_version_id
- tool_binding_id
- approval_id / credential_binding_id
- idempotency_key
- policy_version / policy_reason_code
- status: planned | running | succeeded | failed | unknown | cancelled
- side_effect
- arguments_digest
- planned_at / started_at / finished_at
- error_code / error_category
- attempt_count
```

`unknown` 不是普通 `failed`，Non-idempotent Tool 不得盲目重试。

### 4.6 ExecutionAttempt

```text
ExecutionAttempt
- id / tenant_id / execution_id
- attempt_number
- status: running | succeeded | failed | unknown | cancelled
- started_at / finished_at
- error_code / error_category
- upstream_status
```

一个 ToolExecution 表达一次业务意图，多个 ExecutionAttempt 表达同一意图的有限传输重试。

### 4.7 AuditEvent

```text
AuditEvent
- id
- tenant_id
- occurred_at
- trace_id / request_id / execution_id
- actor_id
- action
- resource_type / resource_id
- outcome
- arguments_digest
- policy_version / reason_code
- metadata_json（只允许脱敏标量）
```

Audit 使用 Append-only 语义。S3-5 决定与 Approval/Execution 使用同一 PostgreSQL 短事务同步写入，
详见 ADR-0010；未来投递外部 SIEM 再增加 Outbox，不让外部网络调用进入当前事务。

## 5. Tool Search Embedding Projection

S4 不建设 KnowledgeDocument/KnowledgeChunk 主线。pgvector 直接服务 Tool Semantic Retrieval：

```text
ToolSearchEmbedding
- id / tenant_id / tool_version_id
- embedding_model / embedding_dimensions
- source_digest
- embedding vector(n)
- indexed_at
```

它是 Published ToolVersion 的可重建 Search Projection，不进入 ToolVersion 生命周期所有权。完整设计见
[内建 Meta Tool 与 Hybrid Tool Search](../架构/04_内建MetaTool与HybridToolSearch.md)。

## 6. PostgreSQL 物理基线

S2 第一批模型统一使用：

- 应用生成 UUID 作为主键；
- `timestamptz` 保存时间；
- JSON Schema、Normalized Operation、Binding Config 使用 JSONB；
- 状态字段使用字符串 Enum + Check Constraint，避免早期 PostgreSQL Enum 迁移负担；
- 所有业务唯一约束包含 Tenant Scope；
- 业务数据不依赖数据库 `create_all()`，Alembic 是唯一 Schema Source of Truth；
- 默认不使用物理级 Cascade Delete 删除历史版本和导入证据。

## 7. 索引与约束

S2 至少包含：

- Upstream `(tenant_id, namespace, name)` 唯一；
- Tool `(tenant_id, canonical_name)` 唯一；
- ToolVersion `(tool_id, version)` 唯一；
- 每个 Tool 最多一个 Published Version 的 Partial Unique Index；
- ToolVersion `schema_digest` 索引；
- ToolVersion `(tenant_id, status)` 索引；
- ToolBinding `tool_version_id` 唯一；
- ImportJob `(tenant_id, source_digest, created_at)` 查询索引；
- ImportedOperation `(import_job_id, operation_key)` 唯一；
- ImportedOperation `(tenant_id, review_status)` 索引；
- 后续 Catalog Search 使用 FTS GIN；
- 后续 Audit 使用 `(tenant_id, occurred_at)`；
- 后续 Execution 使用 `trace_id/request_id`；
- 后续 Approval 使用 `(status, expires_at)`。
- Execution Idempotency 使用 `(tenant_id, principal_id, tool_version_id, idempotency_key)` Partial
  Unique Index；
- ExecutionAttempt 使用 `(execution_id, attempt_number)` Unique Index。

S3-5 已落地上述 Approval、Execution、Audit Index；“后续”只保留为原始规划语境。

## 8. 事务边界

### 8.1 ImportJob

```text
事务 A：创建 pending ImportJob
事务外：读取并解析 OpenAPI
事务 B：写入 ImportedOperations + 标记 completed
失败事务：标记 failed + error_summary
```

不持有数据库事务等待文件、URL 或外部 HTTP。

### 8.2 Review/Draft

```text
锁定 ImportedOperation
→ 更新 Review Result
→ 创建/更新 Draft ToolVersion
→ 创建/更新 Draft ToolBinding
→ 回写 Draft IDs
→ 同一事务提交
```

### 8.3 Publish

首版 Publish 使用单数据库事务：

```text
锁定 Tool 与 Draft ToolVersion
→ 验证 Review Accepted
→ 验证 Draft Binding 完整且同 Tenant
→ Retire 旧 Published Version/Binding
→ Publish 新 ToolVersion/Binding
→ 激活 Tool
→ 提交
```

任何一步失败都不得出现 Published ToolVersion 没有 Published Binding 的状态。

Audit 是否与 Publish 原子提交留给 ADR-0010；S2 先暴露 Domain Event/Audit Port，不宣称跨边界原子性。

### 8.4 Runtime

- Policy Decision 不持有数据库事务等待 Upstream；
- Execution 在外部调用前记录 `planned/executing`；
- Approval Consume 使用条件更新或行锁；
- Credential Value Resolve 不写入业务表；
- 未知执行结果单独建模。

## 9. 旧 Java 表映射

| 旧表 | NexusMCP 去向 | 处理 |
|---|---|---|
| `mcp_gateway` | `upstream_service` 或旧 Gateway 配置 | 重新解释语义，不直接导入 |
| `mcp_gateway_auth` | 后续 Inbound Auth/Principal/Grant | 不迁移明文 API Key |
| `mcp_gateway_tool` | `tool` + `tool_version` | 拆分稳定身份与版本化契约 |
| `mcp_protocol_http` | `tool_binding.binding_config_json` | Secret Header 改为 CredentialBinding |
| `mcp_protocol_mapping` | `imported_operation.normalized_operation_json` | 不作为最终 Tool Schema 行模型 |
| Session/Redis | Legacy Compatibility Runtime | 不进入 Modern Domain 主模型 |

## 10. 数据迁移原则

- 不导入旧 SQL 中的示例 API Key；
- 不导入真实或未知来源 Header；
- 不继承历史 Session；
- 只使用脱敏后的 OpenAPI Fixture 和 Tool Metadata；
- 迁移脚本单向、幂等、可 Dry Run；
- 迁移报告列出 skipped/rejected/review_required；
- 新数据库以 Alembic Migration 为唯一 Schema Source of Truth。
