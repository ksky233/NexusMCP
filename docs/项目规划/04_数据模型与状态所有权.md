# 04｜数据模型与状态所有权

> 状态：概念模型草案
> 原则：先定义谁拥有状态，再设计表；旧 MySQL 表只作为迁移输入。

## 1. 状态所有权总表

| 领域 | 拥有的核心状态 | 不拥有 |
|---|---|---|
| Identity | Tenant、Principal、Role/Claims 映射 | 上游 SaaS Token 明文 |
| Registry | MCP Server、Transport、Version、Health | Agent Session |
| Catalog | Tool Metadata、Schema、Publish Status、Search Document | Tool Credential |
| OpenAPI Import | Source、Import Job、Draft Tool、Review Result | Runtime Tool Execution |
| Policy | Subject/Resource/Action Rule、Decision | Secret Value |
| Credential | Secret Reference、Binding、Grant Metadata | Secret 出现在 Tool Schema |
| Approval | Approval Request、Decision、Expiry、Argument Digest | Channel UI Session |
| Gateway | Execution、Idempotency、Outcome | 长期 Agent Memory |
| Audit | Append-only Event / Digest / Redaction | 完整敏感 Payload |
| RAG Demo | Document、Chunk、Embedding、Source | NexusMCP Tool Catalog 本体 |

## 2. MVP 核心实体

### 2.1 Tenant / Principal

即使第一版只有一个本地 Tenant，也建议核心表带 `tenant_id`，从一开始测试行级隔离。

```text
Tenant
- id
- name
- status

Principal
- id
- tenant_id
- type: user | service | agent
- external_subject
- display_name
- status
```

第一版不建设完整用户中心；Principal 可以从签名 Token claims 映射或使用本地 fixture。

### 2.2 MCPServer

```text
MCPServer
- id
- tenant_id
- namespace
- name
- description
- owner
- status: draft | published | disabled
- transport_type
- endpoint
- protocol_min/max
- auth_scheme
- config_json（非敏感）
- version
- created_at / updated_at
```

Endpoint 必须经过 URL 校验，不能允许 Control Plane 任意配置内网/metadata 地址。

### 2.3 ToolDefinition

```text
ToolDefinition
- id
- tenant_id
- server_id
- canonical_name
- display_name
- description
- input_schema_json
- output_schema_json（可选）
- schema_digest
- version
- tags
- owner
- side_effect: read_only | idempotent_write | non_idempotent_write | unknown
- status: draft | review | published | disabled
- visibility
- search_document
- created_at / updated_at / published_at
```

Tool Schema 使用 JSONB 保存，不沿用旧项目“每个 Schema 字段一行”的 `mcp_protocol_mapping` 作为主模型。字段级映射只在 OpenAPI Import 的中间表示中存在。

### 2.4 OpenAPIImport

```text
OpenAPIImport
- id
- tenant_id
- source_type: url | upload | local_fixture
- source_ref
- source_digest
- openapi_version
- status
- allowlist_snapshot
- error_summary
- created_by
- created_at
```

```text
ImportedOperation
- id
- import_id
- operation_id
- method
- path
- normalized_schema
- generated_tool_name
- conflict_status
- review_status
```

Import 产生 Draft，不直接 Publish。

### 2.5 ToolPolicy

第一版保持简单、可解释：

```text
ToolPolicy
- id
- tenant_id
- subject_type / subject_id
- resource_type / resource_id
- action
- effect: allow | deny | require_approval
- condition_json
- priority
- status
- version
```

默认决策推荐 `DENY`。明确规则优先级并测试冲突，不在第一版引入通用 Rego/Cedar Engine。

### 2.6 CredentialBinding

```text
CredentialBinding
- id
- tenant_id
- tool_id/server_id
- principal_scope/role_scope
- provider
- secret_ref
- grant_type: user | service
- scopes
- status
- expires_at（metadata）
```

`secret_ref` 指向环境、本地开发 Secret Store 或未来 Vault。Audit 只记录 binding id，不记录 Secret。

### 2.7 ApprovalRequest

```text
ApprovalRequest
- id
- tenant_id
- principal_id
- agent_id
- tool_id
- arguments_digest
- arguments_redacted
- status: pending | approved | rejected | expired | consumed
- request_state_digest
- expires_at
- decided_by
- decided_at
```

Approval 必须只能消费一次，且重新执行前再次验证 Principal、Tool Status、Policy Version 和参数摘要。

### 2.8 ToolExecution

```text
ToolExecution
- id
- tenant_id
- request_id
- trace_id
- principal_id
- agent_id
- tool_id / tool_version
- protocol_era
- idempotency_key
- policy_decision
- credential_binding_id
- status: planned | executing | succeeded | failed | unknown
- arguments_digest
- latency_ms
- error_code
- started_at / finished_at
```

对于 non-idempotent Tool，`unknown` 不是普通 `failed`，不能自动重试。

### 2.9 AuditEvent

```text
AuditEvent
- id
- tenant_id
- occurred_at
- trace_id / request_id / execution_id
- actor_type / actor_id
- action
- resource_type / resource_id
- decision
- status
- payload_mode: metadata | redacted
- payload_digest
- details_json（已脱敏）
```

Audit 采用 append-only 语义。修改配置产生新 Event，而不是覆盖历史。

## 3. RAG Demo 数据

RAG 是示例下游能力，不与 Tool Catalog 混表：

```text
KnowledgeDocument
- id
- source
- title
- content_digest
- metadata
- status

KnowledgeChunk
- id
- document_id
- chunk_index
- text
- embedding
- metadata
```

Tool Catalog Search 使用 FTS；Knowledge Search 使用 pgvector。两者的索引、评测和状态所有权独立。

## 4. 旧表映射

| 旧表 | 新去向 | 说明 |
|---|---|---|
| `mcp_gateway` | `mcp_server` 或 gateway configuration | 需拆清 Gateway 与 Server 语义 |
| `mcp_gateway_auth` | inbound credential + principal/grant | 不保留明文 API Key |
| `mcp_gateway_tool` | `tool_definition` | 增加 schema/status/owner/tags/side_effect |
| `mcp_protocol_http` | server/tool endpoint config | Secret Header 改为 Credential Binding |
| `mcp_protocol_mapping` | OpenAPI ImportedOperation 中间表示 | 不作为最终 Tool Schema 存储 |
| Session tables/Redis | Legacy compatibility runtime | 不进入 Modern Domain 主模型 |

## 5. 索引与约束

至少考虑：

- `(tenant_id, namespace, name)` 唯一；
- `(tenant_id, canonical_name, version)` 唯一；
- `schema_digest` 索引；
- `status + tenant_id`；
- Tool Search FTS GIN；
- Audit `tenant_id + occurred_at`；
- Execution `trace_id` / `request_id`；
- Approval `status + expires_at`；
- Idempotency Key 在作用域内唯一；
- RAG embedding vector index 在数据达到规模后再建立并 Benchmark。

## 6. 事务边界

推荐：

- Import Source + Operations 同一导入事务或可恢复 Job；
- Publish Tool 同时写新版本、状态和 Audit；
- Policy Decision 不持有数据库事务等待 Upstream；
- Execution 先落 planned/executing，再执行外部调用；
- Approval consume 使用条件更新/行锁防重复；
- Audit 写入策略明确同步/异步边界；
- Credential Value Resolve 不写入业务表。

## 7. 数据迁移原则

- 不导入旧 SQL 中的示例 API Key；
- 不导入真实或未知来源的 Header；
- 不继承历史 Session；
- 只使用脱敏后的 OpenAPI Fixture 和 Tool Metadata；
- 所有迁移脚本单向、幂等、可 dry-run；
- 迁移报告列出 skipped/rejected/review_required；
- 新数据库以 Alembic Migration 为唯一 schema source of truth。

## 8. 待验证点

- Tool Version 采用独立表还是单表多版本；
- Policy Condition JSON 的最小表达能力；
- Audit 同步落库的性能影响；
- Tool Catalog snapshot/cache 的存储方式；
- Approval 的 MRTR `request_state` 是否独立持久化；
- pgvector 的 Embedding 维度和索引类型。

这些进入 [08｜ADR 与待决策清单](./08_ADR与待决策清单.md)，不在建表前拍脑袋固定。
