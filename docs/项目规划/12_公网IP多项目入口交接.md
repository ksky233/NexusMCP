# 公网 IP 多项目入口交接

> 状态：Completed / Security Cleanup Pending
> 日期：2026-09-07  
> 接手方：DualStruct Codex  
> 目标：放弃本轮域名/ICP 依赖，以一个项目入口页和两个独立 HTTP 端口完成短期求职展示

## 1. 背景与决策

腾讯云中国大陆服务器会在 TLS SNI 阶段阻断当前未备案的 `dearloom.me`。已经验证：

```text
域名 + SNI                              → TLS Reset
https://150.158.20.106                  → TLS/HTTP 正常
https://150.158.20.106 + NexusMCP Host  → NexusMCP 200
```

这不是容器、证书或 Nginx Route 故障。服务器预计 2026 年 12 月到期，Dearloom 是未来品牌名而非当前个人主页，
因此本轮不继续围绕域名改造，也不把备案作为求职 Demo 的前置条件。

目标入口：

```text
http://150.158.20.106/        → ksky233 项目入口页
http://150.158.20.106:18081/  → DualStruct
http://150.158.20.106:18080/  → NexusMCP
```

`18081` 是建议值，实施前须在服务器用 `ss -lntp` 确认未占用。公网仅开放两个 Web Port；Backend、PostgreSQL、
SQLite/Milvus Lite 和 Demo Upstream 不得直接暴露。

## 3. 推荐实施

### A. DualStruct 负责项目入口与自身端口

1. 先读取 DualStruct 仓库规则和现有 P7-D/P7-F 部署记录；
2. 调整 `deploy/production/nginx.tls.conf`：
   - `8080 default_server` 对 IP 请求直接托管 `/usr/share/nginx/landing`，不再强制跳到 HTTPS；
   - 如需保留域名 308，可另建精确 `server_name dearloom.me ...` 的 8080 Server；
   - 新增 Plain HTTP `listen 8081`，复用现有 DualStruct SPA、`/api/` Proxy、上传限制、付费 API 限流和写入护栏；
3. 为 DualStruct Web 增加 Host `18081 → Container 8081`；
4. 更新 `frontend/landing/index.html`：
   - DualStruct 在线体验 → `http://150.158.20.106:18081/`；
   - NexusMCP 在线体验 → `http://150.158.20.106:18080/`；
5. 同步检查 `frontend/landing/nexusmcp.html` 中的返回链接和在线体验链接；
6. 入口页属于 DualStruct Web Image，链接变化后只需重建/发布 DualStruct Web，不要求重建 Backend。

不要把 DualStruct 直接改成 `/dualstruct` 子路径：当前 React 静态资源和 `/api/` 都以 Root Path 为基线，子路径会
引入额外 Base URL、SPA Fallback 和 Proxy Rewrite 改造，独立端口更符合本轮投入边界。

### B. NexusMCP 只调整可复现的公网绑定

建议在 NexusMCP `deploy/production/docker-compose.yml` 中将固定 Loopback 改为显式且安全默认的变量：

```yaml
ports:
  - "${NEXUSMCP_HTTP_BIND_HOST:-127.0.0.1}:${NEXUSMCP_HTTP_PORT:-18080}:8080"
```

服务器 `/opt/nexusmcp/.env` 显式增加：

```dotenv
NEXUSMCP_HTTP_BIND_HOST=0.0.0.0
```

同时在既有 JSON 数组中保留原 Host，并加入：

```text
NEXUSMCP_TRANSPORT_ALLOWED_HOSTS
→ "150.158.20.106"
→ "150.158.20.106:*"

NEXUSMCP_TRANSPORT_ALLOWED_ORIGINS
→ "http://150.158.20.106:18080"
```

Compose/Env 变化只需 Recreate NexusMCP Web/Backend；不需要重建 `672d45f502f3` 镜像，不需要 Migration，不能
重建或删除 PostgreSQL Volume。

实施已完成：Compose 使用 `NEXUSMCP_HTTP_BIND_HOST` 提供安全默认的 Loopback 和服务器显式公网覆盖；生产 Web 已发布 `0.0.0.0:18080 → 8080`，Backend、PostgreSQL 与 Demo Upstreams 均无 Host Port。

### C. 云侧入口

- 腾讯云安全组新增 TCP `18080`、`18081`；
- 保留 80；443 是否保留不影响本轮 IP Demo；
- 不开放 8000、5432、9000；
- 主机没有 `firewalld`，若端口仍不可达，再检查现有 iptables/YJ Firewall 和 Docker Published Port；
- 页面明确标注临时公开演示、共享数据，不放真实凭据和企业数据；公网环境不要配置可被访客反复触发的付费 Key。

## 4. 验收

```text
GET http://150.158.20.106/                  → 200，入口页
入口页 DualStruct 按钮                      → :18081
入口页 NexusMCP 按钮                        → :18080
GET http://150.158.20.106:18081/            → DualStruct SPA
GET http://150.158.20.106:18081/healthz     → ok
GET http://150.158.20.106:18080/            → NexusMCP SPA
GET http://150.158.20.106:18080/healthz     → ok
GET http://150.158.20.106:18080/health/ready → {"status":"ok"}
NexusMCP Modern tools/list                   → 不因 Host Header 被拒绝
```

再确认：

- 两个项目的 Backend/Database 仍只在 Docker Network；
- DualStruct Upload Guard、Paid API Rate Limit 不回归；
- NexusMCP Egress Allowlist、Public Demo Identity、Reset 和 Toolset Endpoint 不回归；
- 入口页和项目页不存在 HTTPS 子域名残留跳转。

### 实际结果

- 公网 `/`、`/healthz`、`/health/ready` 返回 200；
- `/health/ready` 经公网 IP Host Header 返回 `{"status":"ok"}`，Allowed Hosts 生效；
- 公网 `/mcp` 协商 Modern `2026-07-28`，`tools/list` 返回 Search-first 发布面的 `nexus.search_tools`；
- 无代理 Chromium 加载 `http://150.158.20.106:18080/`，页面标题为 `NexusMCP Control Plane`，无 Console/Page Error；
- `https://nexusmcp.dearloom.me` 项目介绍页中的在线演示按钮可以打开正确 IP 页面；
- 服务器只发布 NexusMCP Web 18080，8000、5432、9000 保持容器内部；
- Cloudflare Certbot Token、旧续期任务和服务器 443 安全组属于剩余安全清理，不影响当前 Demo。
