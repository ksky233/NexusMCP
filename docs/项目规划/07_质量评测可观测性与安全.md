# 07｜质量、评测、可观测性与安全

> 状态：质量基线
> 原则：没有测试环境与失败分类的数字，不作为项目证据。

## 1. 质量目标

项目需要证明五件事：

1. 协议兼容行为正确；
2. Policy/Credential/Tenant 边界不会被绕过；
3. 副作用 Tool 在重复请求和失败时行为可控；
4. Trace/Audit 能解释一次调用发生了什么；
5. Search/RAG/性能指标可复现。

| 场景 | Modern | Legacy |
|---|---:|---:|
| discover/initialize | `server/discover` | `initialize` |

| tools/call | 必测 | 必测 |

## 4. Golden Cases

第一版准备约 30～50 个 Case：

### Protocol

- Modern discover/list/call；
- Legacy initialize/list/call；
- malformed request；
- unsupported version；
- unknown method；
- cache scope；
- version fallback。

### OpenAPI

- path/query/header/body；
- nested/ref/enum/required；
- duplicate operationId；
- missing operationId；
- binary response；
- malicious URL；
- unsupported schema。

### Policy / Credential

- allow/deny/approval；
- role/agent/tenant difference；
- disabled tool；
- expired credential binding；
- secret redaction；
- token audience mismatch。

### Reliability

- upstream timeout；
- 429/5xx；
- duplicate request；
- client disconnect；
- non-idempotent unknown outcome；
- approval duplicate consume。

## 5. Search Eval

建立 Query → Expected Tool：

```text
query
expected_tool_ids
principal/visibility
top_k
```

指标：

- Hit@K；
- Top-1 Accuracy；
- 权限过滤正确率；
- 无结果率；
- 索引更新一致性；
- Search p50/p95。

Semantic Search 只有在同一数据集上优于 FTS 且收益大于复杂度时才进入主线。

## 6. RAG Eval

建立 Query → Relevant Chunk：

- 15～30 个样例；
- 文档与 Query 使用可公开数据；
- 记录 Chunk 策略、Embedding 和 Top-K；
- 固定数据集版本。

指标：

- Recall@K；
- MRR/Top-1；
- 引用命中率；
- 无答案/低相关度行为；
- retrieval p50/p95；
- NexusMCP 引入的额外延迟。

RAG Eval 的目的不是评测完整 Agent 回答质量，只证明检索和受治理调用链。

### 7.3 Log

结构化日志最少包含：

```text
timestamp
level
service
trace_id
request_id
event
tool_id（如适用）
error_code（如适用）
```

S2-2B-3.5 基线增加：

```text
environment
logger
protocol_era（如适用）
tenant_id（受控内部标识）
tool_version_id（如适用）
duration_ms（如适用）
exception.type / exception.stack（Unexpected Error，禁止异常参数文本）
```

实现规则：

- 使用 Python 标准 `logging`，通过 Bootstrap 集中配置；
- 业务模块使用 `logging.getLogger(__name__)`，不创建项目专用 Logger Wrapper；
- async 请求字段通过受控 `ContextVar` 传播，并在边界退出时 Reset；
- Formatter 只输出字段白名单，不序列化任意 `LogRecord.__dict__`；
- Event Name、Log Key 和 Error Code 使用稳定英文；
- Expected Error 不默认记录 Traceback；Unexpected Error 记录安全 Stack Frame；
- Log Context 不保存 Principal Token、Tool Arguments、Result 或 OpenAPI 正文。

禁止日志：

- API Key/OAuth Token；
- Authorization/Cookie；
- 完整 Transport Context；
- 完整 Tool Arguments；
- Embedding 原文或文档全文。

## 8. Audit

Audit 与普通日志不同：

```text
Log
= 运行诊断，可采样/轮转

Audit
= 谁对什么做了什么，需稳定 Schema 和保留策略
```

Audit 记录：

- actor/principal；
- tenant/agent；
- action/resource；
- policy decision；
- credential binding id；
- arguments digest；
- execution outcome；
- trace/request id；
- latency/error code。

默认 `metadata` 或 `redacted`，不保存完整敏感 Payload。

## 9. Threat Model

Upstream Egress/SSRF 的第一版实施边界见
[ADR-0016｜Upstream Egress 与 SSRF 防护边界](../adr/0016-upstream-egress-and-ssrf-boundary.md)。

### 9.1 主要资产

- Provider/SaaS Credential；
- Tool Schema 与 Endpoint；
- Tenant/Principal Identity；
- Tool Arguments/Results；
- Audit Records；
- RAG Documents；
- Policy Configuration。

### 9.2 主要威胁

- Token passthrough；
- JWT issuer/audience 混淆；
- Tenant/Tool 越权；
- Prompt Injection 诱导危险 Tool；
- OpenAPI Import SSRF；
- Tool Endpoint SSRF；
- Secret Logging；
- Schema/Tool Description Poisoning；
- Retry 重复副作用；
- Approval Replay；
- Header/Body 路由混淆；
- RAG 文档越权或数据投毒；
- Audit 中的敏感数据泄漏。

### 9.3 必测安全场景

- private/loopback/link-local/metadata URL import；
- DNS rebinding 基础防护策略；
- forged tenant/user header；
- token wrong audience；
- disabled/revoked binding；
- approval 参数被修改；
- duplicate idempotency key；
- secret pattern in request/result/log；
- cross-tenant Tool Search；
- cross-tenant RAG filter。

## 10. Retry 与幂等矩阵

| Tool 类型 | 可自动重试 | 要求 |
|---|---|---|
| read_only | 可按错误分类 | timeout/backoff/max attempts |
| idempotent_write | 有条件 | idempotency key/upstream contract |
| non_idempotent_write | 默认不可 | 人工确认或明确幂等协议 |
| unknown | 不可 | 先完成分类 |

只有 network error/timeout/429/5xx 中的可重试子集进入重试。Authentication、Invalid Request、Policy Deny、Content/Schema Error 不重试。

## 11. Benchmark

报告固定包含：

- CPU/内存/操作系统；
- Python/依赖版本；
- PostgreSQL/Redis 配置；
- Tool 数量；
- 并发数；
- payload 大小；
- 是否命中 cache；
- upstream latency；
- p50/p95/p99；
- throughput/error rate；
- Trace/Audit 开关；
- 运行命令和数据文件。

Benchmark 场景：

1. `tools/list`；
2. Tool FTS Search；
3. read-only `tools/call`；
4. Policy + Credential + Audit 全链；
5. Tool Vector/Hybrid Retrieval；
6. Legacy vs Modern 额外成本。
