## 2. 旧项目已有能力与新增能力

| 能力 | 旧 Java 项目 | NexusMCP 目标 |

## 3. OpenAPI Import 工作流

```text
Submit OpenAPI Source
    ↓ Security Validate / Fetch
Parse + Resolve Ref
    ↓
Normalize Operations
    ↓
Generate Draft Tools
    ↓
Collision / Auth / Risk Review
    ↓
Publish Selected Tools
    ↓
Runtime Execute via HTTP Adapter
```

Review 至少展示：

- operationId/name；
- method/path；
- input schema；
- upstream auth requirement；
- side-effect suggestion；
- response content type；
- collision；
- unsupported feature；
- security warning。

## 4. Tool Search 边界

`nexus.search_tools` 是 NexusMCP 内建 Meta MCP Tool：协议层是 Tool，但不进入 Catalog，不拥有
ToolVersion/ToolBinding/Upstream，不经过 OpenAPI Import。它使用保留的 `nexus.*` Namespace，并由
NexusMCP 版本控制。

Agent-facing 契约只暴露两种检索意图：

```text
lexical
= 明确名称、Namespace、Tags、缩写和领域关键词

hybrid
= Lexical FTS + Tool Embedding Vector Search + Rank Fusion
```

不对 Agent 暴露三个重复 Meta Tool，也不在第一版暴露 `semantic` 或 `auto`：

- Vector-only 仅用于内部 Eval/Ablation；
- Auto Router 需要额外置信度与成本算法，延后到真实指标证明需要；
- Agent 已完成前置意图理解，可以先 Lexical，结果不足时自主调用 Hybrid；
- Semantic 与 Hybrid 都要支付 Query Embedding 成本，Hybrid 额外 FTS 成本很小且能保留精确词召回。

第一版 Meta Tool 输入：

```text
query
retrieval_mode: lexical | hybrid（必填）
limit
namespace / side_effect 等业务 Filter（可选）
```

完整 Schema 按需激活，避免一次把全部 Tool Schema 塞入 Agent Context。Tenant、Published、Visibility
和 Policy Filter 必须在返回候选前应用，不允许通过搜索泄漏不可见 Tool。

## 5. 内部 Semantic Tool Retrieval 边界

S4 的 RAG/Embedding 学习直接服务 Tool Selection，不再依赖外部 Knowledge RAG Demo：

```text
Published ToolVersion
→ Canonical Tool Search Document
→ Embedding
→ pgvector
→ Vector Candidates
→ 与 FTS Candidates 进行 Rank Fusion
→ Top-K Tool Metadata
```

第一版以“一条 Published ToolVersion 对应一个 ToolSearchDocument/Embedding”为单位，不把普通 Tool
强行切成多个 Chunk。Search Document 包含规范化名称、描述、Tags、Namespace、Owner、Side Effect
和 Input Field Summary，不直接 Embedding 噪声较大的完整 JSON Schema。

Embedding 是可重建 Search Projection，不进入 ToolVersion 业务事实；建议独立保存
`tool_search_embedding(tool_version_id, model, dimensions, source_digest, vector, indexed_at)`。

边界：

- Publish 事务不调用外部/本地 Embedding Model；
- 第一版通过 CLI/Reindex Job 在 Commit 后构建向量；
- FTS/Vector 使用 Reciprocal Rank Fusion 等 Rank-Based Fusion，不直接相加不可比 Raw Score；
- Eval 对比 FTS-only、Vector-only、Hybrid，但 Agent 只看到 Lexical/Hybrid；
- 不做文档 Chunk/Citation、GraphRAG、知识图谱、多模态、完整 Knowledge Platform；
- 外部企业 RAG 未来仍可通过其 HTTP/OpenAPI 接口作为普通 Upstream 接入；Remote MCP 接入遵循
  ADR-0017 的 Deferred Trigger，不属于当前主线。

## 6. Demo 设计

### Demo A｜Multi-source OpenAPI → MCP

```text
Employee Directory OpenAPI ─┐
Operations OpenAPI         ├─→ 通用 OpenAPI Import
Inventory OpenAPI          ┘
                               ↓
                    Normalized Operations
                               ↓
                   Draft Tool + Tool Binding
                               ↓ Review + Publish
                         NexusMCP Tool Catalog
                               ↓
                     tools/list / tools/call
```

三个上游均为独立、可运行的轻量 Fake API：

| Fake API | 第一版接口 | 主要覆盖 |
|---|---|---|
| Employee Directory | `GET /employees/{id}`、`GET /employees` | Path、Query、分页、只读可见性 |
| Operations | `GET /services/{id}/status`、`POST /services/{id}/restart` | 副作用、Approval、Timeout |
| Inventory | `GET /items/{sku}`、`POST /reservations`、`DELETE /reservations/{id}` | JSON Body、nested/enum、幂等写 |

通用性约束：

- 三个服务使用同一个 Import、Catalog、Binding 和 Runtime 实现；
- NexusMCP 核心不得出现 `if source == operations/inventory/...` 一类场景判断；
- 场景差异只允许由 OpenAPI、Tool Metadata、Binding、Policy 和 Credential 配置表达；
- Fake API 使用内存数据，不建设数据库、管理 UI 或完整业务流程；
- 每个 OpenAPI 保存一份静态 Fixture，同时保留可运行服务用于 E2E。

实施时先用 `directory.get_employee` 跑通第一条纵向切片，再接入 Operations 和 Inventory；后两者不得要求修改 NexusMCP 核心接入流程。

### Demo B｜Policy + Approval + Credential

```text
directory.get_employee         → ALLOW
ops.get_service_status         → ALLOW
ops.restart_service            → REQUIRE_APPROVAL / DENY（按 Principal）
inventory.create_reservation   → ALLOW + Idempotency Key
inventory.cancel_reservation   → ALLOW / DENY（按 Principal）
```

Agent 不持有任何上游 Token；NexusMCP 根据三个 Upstream 各自的 Binding 注入不同的模拟 Service Credential。

### Demo C｜Meta Tool Hybrid Search

```text
Agent
  ↓ nexus.search_tools(query, lexical | hybrid)
NexusMCP Tool Search
  ├── PostgreSQL FTS
  └── Tool Embedding + pgvector
           ↓ Rank Fusion + Governance Filter
      Relevant Tool Metadata
           ↓ Agent Final Selection
      Describe/Activate/Call Tool
```

### Demo D｜Modern / Legacy

同一服务分别由 Modern Client 与 Legacy Client 调用，展示：

- version negotiation；
- modern no-session；
- legacy initialize/session；
- protocol era metrics；
- 相同 Tool 的一致业务结果。

## 7. 功能停止规则

出现以下情况时停止扩展：

- 新功能不能增强核心 Demo 或面试叙事；
- 新功能需要引入一个大型基础设施，但没有评测/负载依据；
- 只是为了和某个开源项目 Feature List 对齐；
- 已经存在成熟库，且自研不能展示新的工程问题；
- 需要真实公司数据或不可公开依赖；
- 会延迟 Must 闭环的测试、README、Demo 或安全证据。
