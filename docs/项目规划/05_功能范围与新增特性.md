## 2. 旧项目已有能力与新增能力

| 能力 | 旧 Java 项目 | NexusMCP 目标 |

| JSON-RPC | 有 | SDK 化 + Golden Cases |
| SSE/Streamable | Legacy sessionful | Modern stateless + Legacy compatibility |
| initialize | 主链路 | 只用于 Legacy |

## 3. OpenAPI Import 工作流

```text
Submit OpenAPI Source
    ↓ Security Validate / Fetch
Parse + Resolve Ref
    ↓
Normalize Operations
    ↓
Generate Draft Tools
    ↓
Collision / Auth / Risk Review
    ↓
Publish Selected Tools
    ↓
Runtime Execute via HTTP Adapter
```

Review 至少展示：

- operationId/name；
- method/path；
- input schema；
- upstream auth requirement；
- side-effect suggestion；
- response content type；
- collision；
- unsupported feature；
- security warning。

## 4. Tool Search 边界

第一版搜索：

```text
exact name
prefix
description FTS
tags
namespace
owner
published/enabled/visibility
```

先过滤权限，再返回候选。完整 Schema 按需获取，避免 Tool 很多时一次把所有 Schema 塞进模型上下文。

不默认做 Semantic Search。触发条件：

- Tool 达到足够规模；
- 多语言/同义词导致 FTS Hit@K 下降；
- Search Eval 证明向量检索有净收益；
- 真实岗位/业务明确要求。



- 不做管理后台、GraphRAG、复杂 Rerank、知识图谱、多模态。

## 6. Demo 设计

### Demo A｜Multi-source OpenAPI → MCP

```text
Employee Directory OpenAPI ─┐
Operations OpenAPI         ├─→ 通用 OpenAPI Import
Inventory OpenAPI          ┘
                               ↓
                    Normalized Operations
                               ↓
                   Draft Tool + Tool Binding
                               ↓ Review + Publish
                         NexusMCP Tool Catalog
                               ↓
                     tools/list / tools/call
```

三个上游均为独立、可运行的轻量 Fake API：

| Fake API | 第一版接口 | 主要覆盖 |
|---|---|---|
| Employee Directory | `GET /employees/{id}`、`GET /employees` | Path、Query、分页、只读可见性 |
| Operations | `GET /services/{id}/status`、`POST /services/{id}/restart` | 副作用、Approval、Timeout |
| Inventory | `GET /items/{sku}`、`POST /reservations`、`DELETE /reservations/{id}` | JSON Body、nested/enum、幂等写 |

通用性约束：

- 三个服务使用同一个 Import、Catalog、Binding 和 Runtime 实现；
- NexusMCP 核心不得出现 `if source == operations/inventory/...` 一类场景判断；
- 场景差异只允许由 OpenAPI、Tool Metadata、Binding、Policy 和 Credential 配置表达；
- Fake API 使用内存数据，不建设数据库、管理 UI 或完整业务流程；
- 每个 OpenAPI 保存一份静态 Fixture，同时保留可运行服务用于 E2E。

实施时先用 `directory.get_employee` 跑通第一条纵向切片，再接入 Operations 和 Inventory；后两者不得要求修改 NexusMCP 核心接入流程。

### Demo B｜Policy + Approval + Credential

```text
directory.get_employee         → ALLOW
ops.get_service_status         → ALLOW
ops.restart_service            → REQUIRE_APPROVAL / DENY（按 Principal）
inventory.create_reservation   → ALLOW + Idempotency Key
inventory.cancel_reservation   → ALLOW / DENY（按 Principal）
```

Agent 不持有任何上游 Token；NexusMCP 根据三个 Upstream 各自的 Binding 注入不同的模拟 Service Credential。

## 7. 功能停止规则

出现以下情况时停止扩展：

- 新功能不能增强核心 Demo 或面试叙事；
- 新功能需要引入一个大型基础设施，但没有评测/负载依据；
- 只是为了和某个开源项目 Feature List 对齐；
- 已经存在成熟库，且自研不能展示新的工程问题；
- 需要真实公司数据或不可公开依赖；
- 会延迟 Must 闭环的测试、README、Demo 或安全证据。
