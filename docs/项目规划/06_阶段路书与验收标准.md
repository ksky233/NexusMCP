## 2. S1｜协议校准

### 学习/分析

- MCP `2026-07-28` 变化；
- Python SDK v2；
- Legacy fallback；
- 本地 Java Streamable/Session 调用链；
- JSON-RPC Golden Messages。

### 产出

```text
protocol-lab/
├── modern_server
├── modern_client
├── legacy_client
└── tests
```

以及：

- Modern vs Legacy Sequence；
- SDK/version/conformance lock；
- Java 调用链阅读记录；
- 至少 10 个协议 Fixture。

### 验收

- 能解释为什么 Streamable HTTP 不等于最新协议；
- Modern 调用不创建 Session；
- Legacy Client 可 fallback；
- `server/discover` / `tools/list` / `tools/call` 可测试；
- Header/Body 不一致被拒绝；
- Trace 标记 protocol era。

### 停止条件

完成上述闭环后停止手写协议，不继续复刻完整 SDK。

### S2-2B-3.5｜Error 与 Logging 基线

该步骤位于 Persistence Adapter 与 Publish Use Case 之间，避免 Publish 直接绑定 FastAPI、MCP 或
SQLAlchemy 异常。

产出：

- `NexusMcpError` 安全错误基类和 Publish 首批错误码；
- MCP/HTTP 各自的错误映射接缝，Domain/Application 不 import 协议类型；
- Python 标准 Logging 的集中配置，不创建自定义 Logger Wrapper；
- JSON/Console 两种输出、稳定 Event Name 和字段白名单；
- 基于 `ContextVar` 的 request/trace/tenant/protocol Log Context；
- Secret/Authorization/Cookie/完整 Arguments 不进入结构化日志；
- Expected Error 与 Unexpected Error 的日志策略和测试。

验收：

- 同一个业务错误可以安全映射为 MCP/HTTP 表达，且保留稳定 `error_code`；
- 客户端响应不包含 Traceback、SQL、内部 URL 或内部异常消息；
- 并发 async Context 不串 request/trace/tenant；
- JSON Log 至少包含 timestamp/level/service/environment/event；
- 绑定 Context 后包含 request_id/trace_id/tenant_id，错误时包含 error_code；
- 非白名单字段和常见 Secret Key 不进入日志；
- Unexpected Exception 的内部日志保留异常类型和 Stack Frame，但不记录异常参数文本。

停止条件：

- 不在本阶段接入完整 OpenTelemetry/Prometheus/Audit；
- 不建立通用错误 DSL；
- FastAPI 管理接口未出现前只建立可注册的 HTTP Handler，不扩展 `/admin/*`。

### 验收

```text
Directory / Operations / Inventory OpenAPI
→ 同一 Import Pipeline
→ 生成 Draft Tool + Tool Binding
→ Review
→ Publish
→ Catalog 可见
```

必须测试：

- path/query/header/body；
- ref/nested/required/enum；
- name collision；
- unsupported/binary response；
- URL allowlist/SSRF；
- disable 后不可见；
- 不同 visibility 的列表差异。

还必须证明：

- 先用 Employee Directory 跑通首条纵向切片；
- Operations 与 Inventory 通过相同流程接入；
- 新增第二、第三个场景时不修改 NexusMCP 核心 Import/Runtime 代码；
- 三个服务拥有独立 Namespace、OpenAPI Fixture 和 Upstream Binding；
- Fake API 总量控制在约 7 个接口，只使用内存数据。

### 停止条件

不做复杂 UI；使用 REST/CLI/简单页面完成 Review 即可。

## 4. S3｜Gateway 与治理

### 产出

- Modern/Legacy Data Plane；
- Internal Principal；
- Tool Resolution；
- Policy；
- Credential Binding/Injection；
- Approval；
- Tool Execution Record；
- Audit；
- error normalization；
- idempotency/side-effect classification。

### 验收

同一个 Tool 对不同身份产生：

```text
User A → ALLOW
User B → REQUIRE_APPROVAL
User C → DENY
```

并证明：

- Secret 不进入模型、日志和 Audit；
- approval 绑定参数摘要；
- approval 只能消费一次；
- read-only retry 与 non-idempotent retry 策略不同；
- timeout/cancel 可传播；
- unknown execution outcome 不会盲目重试。

### 停止条件

不建设通用 Policy DSL 和完整 OAuth Server。

## 5. S4｜Tool Search + 小型 RAG

### Tool Search 产出

- name/description/tags/namespace/owner 搜索；
- published/visibility/policy filter；
- Top-K Metadata；
- 按需 Schema；
- Search Eval。

### RAG 产出

- `demo_knowledge_mcp`；
- CLI ingest；
- pgvector；
- `knowledge.search`；
- source citation；
- 15～30 个 Retrieval Cases。

### 验收

- Tool Search 记录 Hit@K/Top-1；
- 权限过滤不会泄漏不可见 Tool；
- RAG 记录 Recall@K/MRR；
- 无相关结果有明确行为；
- Agent 回答能显示来源；
- NexusMCP Trace 能串到 Knowledge Tool。

### 停止条件

不做 Semantic Tool Search，不做 Rerank/GraphRAG/知识库后台；除非评测或 JD 提供证据。
