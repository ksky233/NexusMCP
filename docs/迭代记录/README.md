# NexusMCP 迭代记录

## 1. 目录职责

`迭代记录` 用于项目达到阶段性可用状态后，串联一次跨模块优化的完整过程：

```text
触发原因
→ 依据的 ADR
→ Before / Target
→ 影响面与兼容性
→ 实施步骤
→ 验证证据
→ 最终结果与遗留项
```

它是一次迭代的导航和交付记录，不替代其他正式事实源：

| 目录 | 负责回答 |
|---|---|
| `架构/` | 当前系统结构和领域边界是什么 |
| `adr/` | 为什么做出某项长期决策 |
| `项目规划/` | 项目阶段和功能准备怎么推进 |
| `实验记录/` | 某个实现阶段具体做了什么、如何验证 |
| `遇见的问题/` | Bug、故障和排查过程 |
| `学习笔记/` | 可以脱离当前项目复用的知识 |
| `迭代记录/` | 一次跨模块改造如何从决策走到完成 |

## 2. 什么时候创建

适合创建迭代记录：

- 项目基本完成后的架构收敛；
- 影响三个及以上模块；
- 涉及公共 Contract、数据模型或兼容性；
- 需要 Before/After 对比；
- 需要分多个 Commit 或工作包完成；
- 能形成独立的工程复盘或作品集叙事。

不需要创建：

- 单处文案修正；
- 局部 Bug；
- 单文件机械重构；
- 普通依赖升级；
- 已经能由一个清晰 Commit 完整表达的改动。

## 3. 文件命名

```text
NN_主题.md
```

例如：

```text
01_ServiceCentricIdentity代码收敛.md
```

编号表示本项目进入稳定阶段后的迭代顺序，不复用 S/W 阶段编号。

## 4. 状态

每份记录必须明确：

```text
Planned
In Progress
Completed
Cancelled
```

`Completed` 必须包含实际验证结果、兼容性结论和最终 Commit；不能因为开始编码或写完计划就标记完成。

## 5. 推荐模板

```markdown
# I-N｜主题

> 状态：Planned
> 触发：...
> 依据：ADR-xxxx

## 目标
## 非目标
## Before
## Target
## 代码影响面
## 数据与兼容性
## 实施步骤
## 验证矩阵
## 风险与回滚
## 完成结果
## 遗留项
```

正文应链接 ADR、架构和问题记录，不复制这些文档的大段内容。
