## 1. 目标

将 S1 的协议实验升级为可安装、可测试、可演进的正式 Python Package，同时只创建当前存在真实职责的目录。

本阶段不实现 OpenAPI Import、数据库、ToolBinding 和真实 `tools/call`。

## 4. 已实现职责

### 4.1 Application Factory

`bootstrap.app.create_app()`：

- 读取或接收 Settings；
- 组装 ToolRepository 和 ListVisibleTools；
- 创建低层 MCP Server；
- 将 MCP Starlette App 挂载到 FastAPI；
- 由父 Lifespan 管理 MCP Session Manager；
- 先注册 Health，再注册 Catch-all MCP Mount。

### 4.2 Settings

`bootstrap.config.Settings`：

- 使用 `NEXUSMCP_` 环境变量前缀；
- 固定 Process Config 与业务配置边界；
- 提供 Environment、Debug、Local Tenant 和 Transport Host/Origin Allowlist；
- 不包含真实 Secret 默认值。

### 4.3 RequestContext

正式 `RequestContext` 不依赖 FastAPI 或 MCP SDK。

MCP Context Adapter 当前：

- 解析 Protocol Version/Era；
- 保留 Request ID；
- 解析合法 `traceparent` 或生成 Trace ID；
- 使用本地 Tenant；
- 在正式 Authenticator 出现前固定为 Anonymous Principal；
- 不信任 S1 中的测试 Principal Header。

### 4.4 Catalog

第一组 Catalog 能力：

- ToolStatus：Draft/Review/Published/Disabled；
- ToolVisibility：Public/Authenticated/Restricted；
- ToolSideEffect 分类；
- ToolDefinition 基本不变量；
- ToolRepository Port；
- ListVisibleTools Use Case；
- InMemoryToolRepository Adapter。

### 4.5 MCP Interface

正式 Adapter 使用 SDK v2 低层 `Server`：

```text
MCP tools/list
→ resolve RequestContext
→ ListVisibleTools
→ ToolDefinition
→ SDK types.Tool/ListToolsResult
```

MCP SDK wire alias 使用 camelCase，但 Python 代码统一使用 SDK 的 snake_case 属性，例如：

```text
input_schema
output_schema
cache_scope
ttl_ms
is_error
```

当前正式 Adapter 只实现 `tools/list`。`tools/call` 仍保留在 S1 实验中，等待 Execution、ToolBinding 和 Connector Context 出现后再迁移，避免把 Fake Executor 带入正式 Core。

## 5. 测试覆盖

新增测试：

- Catalog 生命周期和 Principal 可见性；
- Restricted Tool 必须有允许主体；
- 正式 MCP Adapter 动态输出 Published Tool Schema；
- 正式 `/mcp` HTTP 挂载；
- Application Factory 的 `/health` 路由顺序。

S1 的 Modern/Legacy、动态 Tool、ASGI Context 测试继续保留。

- 尚未建立 CI Workflow。
