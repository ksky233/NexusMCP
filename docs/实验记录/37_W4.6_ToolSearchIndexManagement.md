# W4.6｜Tool Search Index Management

> 日期：2026-08-29
> 状态：完成（本地）

## 1. 目标

补齐“Web 能看到 Embedding Coverage，却不能处理 Pending Tool”的 Control Plane 缺口，并让 Search Lab
区分 RRF 融合分数与底层 FTS/Cosine 分数。

## 2. Index Management

Catalog 新增“检索索引管理”：

- Published、Current、Missing、Stale 计数；
- Embedding Model@Dimensions；
- 普通更新只处理 Missing/Stale；
- 每个 Tool 最新发布版本显示索引状态与 Indexed Time；
- 最近 Job 的状态、Embedded Count、Batch Count 与安全错误码；
- TanStack Query 在 `pending/running` 时轮询，Terminal 后停止。

## 3. 持久化 Reindex Job

新增 `tool_search_reindex_job`：

```text
pending → running → succeeded
                  ↘ failed
```

边界：

- 每租户 Partial Unique Index 限制一个 Active Job；
- 创建 API 返回 `202 Accepted`；
- API Key 只存在后端 Settings/Provider；
- Reindex 复用现有 Canonical Document、Digest、Batch、Upsert Pipeline；
- Current Projection 不重复调用 Provider；
- Web 进程重启时 Active Job 终结为 `reindex_job_interrupted`；
- 第一版使用 FastAPI Background Task，不声称已经是分布式 Worker。

新增 Admin Operation：

```text
GET  /admin/tool-search/index-status
POST /admin/tool-search/reindex-jobs
GET  /admin/tool-search/reindex-jobs
GET  /admin/tool-search/reindex-jobs/{job_id}
```

Admin Contract 从 30 扩展为 34 个稳定 Operation。

## 4. Search Lab Diagnostics

Hybrid Result 保留 RRF 排序，同时向 Admin Search Lab 返回：

```text
rrf_score
lexical_rank
lexical_score (PostgreSQL ts_rank_cd)
vector_rank
vector_cosine_similarity
```

UI 使用“RRF 分数”作为明确标题，不额外堆叠重复说明。Lexical 结果显示自身排名与 FTS 分数。Agent-facing
Meta Tool 仍只消费最终候选，不依赖 Admin-only Diagnostics。

## 5. 本地启动链修复

手工注册首次暴露两个问题：

1. Development Database Migration 后没有 Local Tenant；
2. Registry Repository 把所有 `IntegrityError` 映射成 `upstream_conflict`。

修复后：

- Development Control Plane Lifespan 幂等插入 Local Tenant；
- 只有 PostgreSQL `23505 unique_violation` 映射为 `upstream_conflict`；
- `23503 foreign_key_violation` 不再被伪装成名称重复。
