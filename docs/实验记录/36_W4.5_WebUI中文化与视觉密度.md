# W4.5｜Web UI 中文化与视觉密度

> 日期：2026-08-29  
> 状态：完成（本地）

## 1. 目标与边界

本阶段只调整 Web Control Plane 的展示语言与视觉密度，不修改 Admin API、领域模型或 MCP Contract。

- 导航、页面标题、说明、表单、操作按钮、空状态与安全错误提示使用中文；
- API 字段、状态码、错误码、日志字段、Request/Trace ID 与代码标识保持英文；
- Tool、Principal、Namespace、Policy、Binding、Schema 等领域词在需要精确表达时保留；
- 不建设运行时 i18n、多语言切换或第二套 Theme。

## 2. v2 视觉校准

对比“黑白-细硬”v1 与 v2 后，提取并应用以下差异：

- Eyebrow、Component Label、Field Label 加深并提高字重；
- Panel、Filter、Table Frame 与 Form Control 的 1px Border 提高对比度；
- Hover/Focus 边界更明确，Secondary Button 不再与普通背景混在一起；
- Table Row 与 Section Divider 更稳定；
- State Panel 高度与内边距略微收紧；
- Card Hover 位移收敛至 1px，Shadow 更紧，不制造漂浮式营销感。

“边框更粗”在实现上主要体现为提高 Slate Alpha，而不是将全部 Border 改为 2px，因此仍符合“细硬”风格。

## 3. 中文化策略

采用“中文句子 + 必要英文领域词”的方式：

```text
工具调用、审批管理、执行与审计
Tool / Principal、Namespace、Input Schema、Hybrid RRF
Request ID、Trace ID、Policy、Binding Digest
```

后端返回的稳定错误 `code` 保持英文；前端自身产生的安全错误说明使用中文。后端 Problem Details 的安全
`detail` 原样展示，以免前端建立一套容易漂移的错误翻译表。

## 4. 测试影响

Accessible Name 是浏览器自动化 Contract 的一部分，因此中文化后同步更新：

- React Testing Library 的 Role/Label/Text Selector；
- Playwright 的导航、表单、按钮、Dialog 与 Timeline Selector；
- `html lang` 从 `en` 改为 `zh-CN`；
- 日期与数字展示使用 `zh-CN` Locale。

## 5. 验证结果

- Admin API Codegen：通过；
- Frontend Format/Type Check/Lint/Build：通过；
- Vitest/RTL/MSW：`20 passed`；
- Multi-stage Docker Build：通过；
- Full-stack Playwright：`2 passed / 7.9s`；
- Desktop 1440×900 生产镜像截图：人工检查通过；
- Browser Publish→MCP Call→Execution/Audit 主链：通过。

## 6. 结论

W4.5 让界面更符合国内求职展示与企业后台使用习惯，同时守住了技术 Contract 的英文边界。视觉仍是同一套
黑白灰极简系统，只是从偏空气感的展示页面收敛为边界更清楚、信息扫描更稳定的治理控制台。
