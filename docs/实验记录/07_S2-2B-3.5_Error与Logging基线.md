# S2-2B-3.5｜Error 与 Logging 基线验收

> 日期：2026-08-25  
> 范围：协议无关 Error Contract、MCP/HTTP 映射接缝、结构化 Logging、async Log Context、
> Secret Logging 安全测试

## 1. 为什么在 Publish 前实现

Publish 会同时遇到业务状态错误、Tenant 越界、并发冲突和数据库约束异常。如果 Use Case 直接抛
`HTTPException`、MCP Error 或 SQLAlchemy `IntegrityError`，Application 将被具体协议和框架污染。

本阶段先建立：

```text
Domain/Application Error
          │
          ├── MCP Adapter  → MCP Error Result / JSON-RPC Error
          ├── Admin HTTP   → HTTP Status + Safe JSON
          └── Import Job   → Failed Status + error_code（后续）
```

本阶段不接入完整 OpenTelemetry、Metric、Audit 或 `/admin/*` API。

## 2. Error Contract

`NexusMcpError` 明确分离：

```text
str(error)
= 内部诊断消息，只允许受控内部使用

error.code
= 稳定英文机器码

error.safe_message
= 可以进入 MCP/HTTP/Job 的安全英文消息
```

首批 Publish 前置错误：

```text
tool_not_found
tool_version_not_found
tool_binding_not_found
invalid_tool_state
tenant_boundary_violation
publish_conflict
upstream_not_active
schema_digest_mismatch
binding_digest_mismatch
```

HTTP Status 不属于 Exception；由 HTTP Adapter 根据 `error.code` 映射。MCP Adapter 使用同一 Code，
但返回 MCP Tool Result/JSON-RPC 表达。

## 3. HTTP 与 MCP 边界

MCP 已有 `to_call_tool_error()`，只返回 `safe_message` 和
`com.nexusmcp/errorCode`，不会返回内部 Exception Message。

HTTP 提供可注册的 `nexusmcp_error_handler()`：

```json
{
  "code": "invalid_tool_state",
  "message": "The tool cannot be changed from its current state.",
  "request_id": "request-..."
}
```

该 Handler 当前不注册到承载 `/mcp` 的宿主 FastAPI App。未来 `/admin` 使用独立 Sub-Application 或
明确边界时再注册，防止 MCP 子应用异常被错误翻译成普通 HTTP JSON。

Unexpected Exception 继续由 ASGI/MCP Server 返回安全通用错误；项目结构化日志记录异常类型和安全
Stack Frame。

## 4. 结构化 Logging

继续使用标准库：

```python
logger = logging.getLogger(__name__)
```

没有创建 `CustomLogger`、`LogUtils` 或全局业务 Logger。`configure_logging()` 只在部署入口集中设置：

- Console/JSON Formatter；
- Service/Environment/Level；
- Root Handler；
- 字段白名单和安全异常格式。

JSON Log 基础字段：

```text
timestamp
level
service
environment
logger
event
```

Context/可选字段：

```text
request_id
trace_id
tenant_id
protocol_era
tool_id
tool_version_id
error_code
duration_ms
tool_count
```

Event Name 使用稳定 `snake_case` 英文。非结构化 Message 被归一为
`unstructured_log_event`，避免任意文本直接成为稳定日志协议。

## 5. async Log Context

`bind_log_context()` 使用 `ContextVar`：

- 支持嵌套增量绑定；
- 离开 Context 自动 Reset；
- 并发 Task 不共享 request/trace/tenant；
- 不保存 Principal Token、Arguments、Result 或 OpenAPI 正文。

MCP `tools/list` 边界绑定 RequestContext，并记录：

```text
mcp_tools_list_completed
mcp_request_rejected
mcp_request_failed
```

Expected Error 记录 Warning 和 `error_code`，不记录 Traceback；Unexpected Error 记录安全 Exception
Type/Stack 后重新抛出，不吞掉错误。

## 6. Secret Logging 防线

Formatter 只读取明确白名单，不序列化整个 `LogRecord.__dict__`。因此以下 Extra 不进入输出：

```text
authorization
cookie
api_key
tool_arguments
```

常见 Secret Assignment/URL Credential 会被 Redact。Unexpected Exception 不输出 `str(exception)`，
只输出：

```json
{
  "exception": {
    "type": "RuntimeError",
    "stack": [
      {"file": "...", "line": 1, "function": "..."}
    ]
  }
}
```

这避免异常参数中的 Token、密码或 SQL 值进入日志。

## 7. 开发中确认的边界问题

### 7.1 REST 全局 Handler 不能覆盖 MCP Mount

宿主 FastAPI 同时挂载 `/mcp`。如果把 `NexusMcpError` Handler 注册到整个宿主 App，MCP 子应用向外冒泡
的异常可能被翻译成 REST JSON，破坏 MCP Transport Contract。

因此当前只提供 Handler 注册函数，留给未来独立 `/admin` HTTP 边界使用。

### 7.2 Traceback 也可能泄漏 Secret

普通 `logging.exception()` 会把 `str(exception)` 放在 Traceback 最后一行；异常消息可能包含 URL、SQL
参数或 Token。本项目 Formatter 只保留异常类型与 Stack Frame，不输出异常参数文本。

### 7.3 ContextVar 必须 Reset

ASGI Worker 会长期复用 Event Loop。如果只 Set 不 Reset，下一个请求可能继承前一个 Tenant/Trace。
`bind_log_context()` 使用 Token 在 `finally` 中恢复旧 Context，并通过并发测试验证隔离。
