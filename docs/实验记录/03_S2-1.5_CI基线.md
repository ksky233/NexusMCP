## 1. CI 在哪里运行

GitHub Actions CI 运行在 GitHub 创建的临时 Ubuntu Runner，不调用开发者本机：

```text
Push / Pull Request / Manual Dispatch
→ 创建干净 Ubuntu Runner
→ Checkout Repository
→ 安装 uv/Python/依赖
→ 执行质量门禁
→ 上传状态到 GitHub
→ 销毁 Runner
```

本地检查负责快速反馈，云端 CI 负责证明仓库在干净、独立环境中可复现。两者使用相同命令，但不互相替代。

## 2. 触发条件

```text
Push to main
Pull Request
workflow_dispatch 手动触发
```

并发策略会取消同一 Branch/Ref 上已经过时的运行。

## 3. 安全与可复现性

- Workflow Token 只有 `contents: read`；
- Checkout 不保留 Push Credential；
- GitHub Action 使用完整 Commit SHA 固定；
- uv 固定为 `0.12.5`；
- Python 读取仓库 `.python-version`；
- 先运行 `uv lock --check`，再使用 `uv sync --frozen`；
- 不使用 Repository Secret；
- Runner Timeout 为 15 分钟。

Action 基线：

```text
actions/checkout v7.0.1
astral-sh/setup-uv v9.0.0
```

## 4. 云端门禁

```text
uv lock --check
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run basedpyright
uv run python -m pytest -q
uv build --clear
```

## 5. 本地与云端分工

| 场景 | 本地 | GitHub CI |
|---|---|---|
| 文档/注释 | Diff Check | Push 后自动运行完整 Workflow |
| 小型 Python 改动 | Targeted Test/Ruff | Push/PR 后完整 Workflow |
| 跨模块/依赖/协议 | 本地完整相关门禁 | Push/PR 后再次完整运行 |
| 合并证明 | 可选截图/日志 | GitHub Check 为事实源 |
