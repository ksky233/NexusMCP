# NexusMCP 业务词汇、核心用例与限界上下文

> 状态：Accepted，已作为 ADR-0001 的领域输入
> 阶段：S2-0｜领域与结构冻结
> 日期：2026-08-24
> 身份边界修订：2026-08-30，按 ADR-0019 收敛为 Admin Operator + Agent Service
> 作用：统一领域语言，冻结第一版业务边界、状态所有权和依赖方向，为 ADR-0001 与正式 Python 工程骨架提供输入。
> 不在本文冻结：数据库表结构、ORM Model、最终文件数量、SDK 精确调用代码。

## 1. 文档结论

NexusMCP 的核心领域不是员工、运维、库存或支付，而是：

```text
企业能力接入
→ Tool 标准化与发布
→ MCP 暴露
→ Agent Service 身份、策略、凭据、审批、执行和审计
```

第一核心业务链是：

> 将企业 HTTP/OpenAPI 服务接入统一 Tool Catalog，生成并发布 MCP Tool；Agent Service 调用 Tool 时，由
> NexusMCP 完成机器身份解析、可见性与 Policy 判断、Credential 注入、上游执行、结果规范化、Trace 和
> Audit。

早期曾把 Remote MCP Server 设计为第二类接入来源，但 ADR-0017 已将其延后：当前没有足够明确的组织级
Upstream 场景，不进入正式主线。下文中的 Remote MCP 词汇只代表历史预留设计，不代表当前可用能力。

当前确认的领域边界：

```text
Registry
OpenAPI Import
Tool Catalog
Connectors
Identity
Policy
Credentials
Approval
Execution
Audit
```

Control Plane 与 Data Plane 是用例和运行边界，不是两套重复领域模型。

## 2. 项目定位与边界

### 2.1 一句话定位

> NexusMCP 是企业 Tool 接入与治理平台：把内部 OpenAPI/HTTP API 转化并发布为受治理 MCP Tool，通过
> MCP 向 Agent 暴露，并在调用链上统一执行身份、策略、凭据、审批和审计。

### 2.2 三层能力

| 层次 | 核心职责 | 单独做到该层时的形态 |
|---|---|---|
| API → MCP Converter | 将 OpenAPI Operation 标准化为 ToolDefinition 和 ToolBinding | OpenAPI 转换器 |
| MCP Gateway Runtime | 实现 Tool 发现、调用、上游执行和结果映射 | MCP Gateway |
| Enterprise Governance | Identity、Policy、Credential、Approval、Audit、Trace | NexusMCP 完整定位 |

### 2.3 明确不属于核心领域

- Employee Directory、Operations、Inventory 等 Demo 的业务规则；
- 完整 Agent Runtime；
- LLM Gateway；
- 自研 OAuth Authorization Server；
- Secret Manager 本身；
- 完整 RAG/知识库平台；
- 大型管理前端、复杂 Workflow/Tool Builder；S6 只增加 Local Web Control Plane MVP；
- 为架构图而拆分微服务。

三个 Fake API 只用于证明通用接入能力，`src/nexusmcp` 不得 import Demo 代码或出现按场景名称分支的 Parser、Gateway、Policy、Connector。

## 3. Actors

| Actor | 主要目标 | 主要交互 |
|---|---|---|
| Admin Operator | 管理企业能力和治理边界 | Registry、Import、Review、Publish、Policy、Credential、Approval、Audit |
| Agent Service | 通过受信 Service Principal 发现并调用 Tool | `tools/list`、Tool Search、`tools/call` |
| Upstream System | 实际提供企业能力 | 当前为企业 HTTP/OpenAPI；Remote MCP Deferred |

说明：普通员工不是 NexusMCP Actor。员工使用业务系统或 Agent 助手；员工身份、会话用户和员工行为追踪由
上层 Agent 服务负责。NexusMCP 不接收 `end_user_reference`。身份产品边界由 ADR-0019 冻结。

## 4. 统一业务词汇

### 4.1 Identity 与请求上下文

| 词汇 | 定义 | 不代表 |
|---|---|---|
| Tenant | 数据、配置和策略的最高隔离作用域 | 部署实例或 HTTP Session |
| Principal | 认证后得到的可信调用主体，主线为 AdminPrincipal 或 AgentServicePrincipal | 员工账号或客户端自报 Header |
| Agent Service | 调用 MCP Data Plane 的受信机器服务 | Agent 会话中的最终员工 |
| RequestContext | 一次请求中可信的协议、身份和 Trace 上下文 | Secret、完整 Arguments 或数据库 Session |
| Protocol Era | `modern` 或 `legacy` 协议时代标记 | 业务权限和用户身份 |

建议的 RequestContext 信息：

```text
request_id
trace_id
protocol_version
protocol_era
tenant_id
principal_id
authn_method
policy_snapshot
```

### 4.2 Registry 与上游系统

| 词汇 | 定义 | 状态所有者 |
|---|---|---|
| UpstreamService | NexusMCP 接入的企业能力来源 | Registry |
| HttpUpstream | 通过 HTTP/OpenAPI 提供能力的 UpstreamService | Registry |
| RemoteMcpServer | Future Connector 的历史预留词汇，当前不接受注册/执行 | Deferred |
| UpstreamVersion | 上游配置或能力快照的版本信息 | Registry |
| HealthStatus | 上游最近一次健康检查和调用健康摘要 | Registry/Health |
| Namespace | Tool 名称的业务/来源作用域，用于组织和解决名称冲突 | Registry/Catalog 协作 |

Registry 回答：

```text
接入了哪些上游系统？
它们由谁维护？
使用什么 Transport？
Endpoint 和非敏感配置是什么？
当前是否可用？
```

### 4.3 OpenAPI Import

| 词汇 | 定义 | 状态所有者 |
|---|---|---|
| OpenApiSource | OpenAPI 文档的来源描述、Digest 和读取方式 | OpenAPI Import |
| OpenApiImportJob | 一次读取、校验、解析、标准化和生成 Review Report 的导入任务 | OpenAPI Import |
| ImportedOperation | 某次 ImportJob 从 OpenAPI Path/Method 中解析出的标准化 Operation | OpenAPI Import |
| NormalizedSchema | 解析 `$ref` 和参数位置后得到的确定性内部 Schema | OpenAPI Import |
| ImportReviewReport | 名称冲突、不支持特性、安全风险和发布建议 | OpenAPI Import |
| Draft Tool Candidate | 从 ImportedOperation 生成、尚未发布的 Tool 候选 | OpenAPI Import → Catalog |

一个 ImportJob 可以产生零个、一个或多个 ImportedOperation：

```text
OpenApiImportJob 1 ── N ImportedOperation
```

它表示来源和生命周期关系，不要求代码将几千个 Operation 一次加载进单个巨大 Aggregate。

### 4.4 Tool Catalog

| 词汇 | 定义 | 状态所有者 |
|---|---|---|
| Tool Catalog | NexusMCP 管理的、可供查询和发布的 ToolDefinition 集合 | Catalog |
| ToolDefinition | Agent 能看到的 Tool 名称、描述、输入/输出 Schema 和业务元数据 | Catalog |
| ToolVersion | ToolDefinition 的不可变发布版本 | Catalog |
| ToolStatus | `draft/review/published/disabled` 等生命周期状态 | Catalog |
| Visibility | 哪类 Principal 有资格发现 Tool 的粗粒度边界 | Catalog/Policy |
| SideEffect | `read_only/idempotent_write/non_idempotent_write/unknown` | Catalog |
| SchemaDigest | Tool Schema 的确定性摘要，用于版本、Diff 和缓存失效 | Catalog |

Tool Catalog 回答：

```text
有哪些 Tool？
Agent 能看见什么？
Tool 的参数契约是什么？
哪个版本已经发布？
Tool 是否被禁用？
Owner、Tags、Namespace 和 SideEffect 是什么？
```

Catalog 不保存真实 Secret，也不负责执行 HTTP/MCP 请求。

### 4.5 Connectors 与执行绑定

| 词汇 | 定义 | 状态所有者 |
|---|---|---|
| ToolBinding | 一个 ToolVersion 到具体执行目标的绑定 | Connectors |
| HttpOperationBinding | HTTP Method、Path、参数位置、响应策略等执行配置 | Connectors |
| RemoteMcpToolBinding | Future Connector 的预留绑定，当前不属于可执行契约 | Deferred |
| Connector | 将通用执行请求转换成上游协议请求的 Adapter | Connectors/Infrastructure |
| Executor | 执行已解析 Binding 的运行时组件 | Connectors/Execution 协作 |

ToolBinding 回答：

```text
这个 Tool 由谁执行？
当前必须使用 HTTP；`remote_mcp` 只有 ADR-0017 触发条件满足并实现 Connector 后才能选择。
对应哪个 Method/Path/Remote Tool？
参数放在 Path、Query、Header 还是 Body？
使用什么 Timeout、Response 和安全策略？
```

### 4.6 Policy、Credential 与 Approval

| 词汇 | 定义 | 状态所有者 |
|---|---|---|
| ToolPolicy | Subject、Resource、Action、Condition 和 Effect 的规则 | Policy |
| PolicyDecision | `ALLOW`、`DENY` 或 `REQUIRE_APPROVAL` | Policy |
| SecretReference | 指向 Secret 保存位置的引用，不包含 Secret 真实值 | Credentials |
| CredentialBinding | Agent Service Principal/Tenant、Tool、Upstream 与 SecretReference 的选择关系 | Credentials |
| CredentialProvider | 根据 SecretReference 从环境或外部 Secret Store 解析真实值的 Port/Adapter | Credentials/Infrastructure |
| ApprovalRequest | 高风险调用的申请、参数摘要、过期和决定状态 | Approval |

必须区分：

```text
Inbound Credential
= Client 用什么证明自己可以访问 NexusMCP

Internal Principal
= NexusMCP 认证后得到的可信主体

Egress Credential
= NexusMCP 调用 Upstream 时使用的 Credential
```

三者不能混用或无条件透传。

### 4.7 Execution 与 Audit

| 词汇 | 定义 | 状态所有者 |
|---|---|---|
| ToolExecution | 一次 Tool 调用的计划、执行、结果和未知状态 | Execution |
| IdempotencyKey | 在定义作用域内识别重复副作用调用的键 | Execution |
| UnknownExecutionOutcome | 无法确认上游是否已经执行成功的状态 | Execution |
| AuditEvent | 对 Actor、Action、Resource、Decision 和 Outcome 的脱敏追加记录 | Audit |
| Trace | 跨 Protocol、Policy、Connector、Upstream、Audit 的诊断链路 | Observability |

`UnknownExecutionOutcome` 不等于普通失败。对于非幂等 Tool，不能因为网络超时就自动重试。

## 5. 核心用例

### 5.1 Control Plane

#### RegisterUpstreamService

```text
输入：Upstream 类型、Endpoint、Owner、Namespace、非敏感配置
输出：UpstreamService
关键规则：Endpoint 安全校验；Secret 不进入普通配置
```

#### ImportOpenApi

```text
输入：Upstream、OpenAPI Source、Operation Allowlist
输出：OpenApiImportJob、ImportedOperations、Review Report
关键规则：Import 产生 Draft，不直接 Publish
```

#### ReviewImportedTool

```text
输入：ImportedOperation、Draft Tool、风险/冲突处理意见
输出：Accepted / Rejected / Needs Change
关键规则：不支持和高风险 Operation 不能静默发布
```

#### PublishTool

```text
输入：Reviewed Draft Tool、Reviewed ToolBinding
输出：Published ToolVersion
关键规则：发布后形成确定性 Schema、Binding 和可追踪版本
```

#### DisableTool

```text
输入：Tool/Version、原因、Actor
输出：Disabled Status + AuditEvent
关键规则：禁用后不可发现、不可调用，缓存必须失效
```

#### SyncRemoteMcpTools（Deferred Future Use Case）

```text
状态：未实现，不属于当前主线
触发：出现多个组织自有 Remote MCP、由企业托管 Agent 使用、且 MCP 是正式 Upstream 接口
未来规则：同步不等于自动发布；Remote Tool 仍需治理
```

#### ConfigureToolPolicy

```text
输入：Subject、Tool、Action、Effect、Condition
输出：Policy Version
关键规则：默认 DENY；冲突优先级确定且可测试
```

#### BindCredential

```text
输入：Agent Service Principal/Tenant Scope、Tool/Upstream Scope、SecretReference
输出：CredentialBinding
关键规则：只保存引用和元数据，不读取/返回 Secret 明文
```

### 5.2 Data Plane

#### ListVisibleTools

```text
输入：RequestContext、Namespace/Cursor/Search Query
输出：当前 Principal 可见的 Published ToolDefinition
关键规则：只返回 Published/Enabled；Visibility 和 Policy 过滤；权限相关缓存隔离
```

说明：Tool 在 `tools/list` 中不可见，不代表调用阶段可以省略授权。客户端可以直接构造 `tools/call`，所以每次调用必须重新解析 Tool 和 Policy。

#### CallTool

```text
输入：RequestContext、Tool Name、Arguments、Idempotency/Request State
输出：Tool Result / Approval Required / Normalized Error
```

核心编排：

```text
Resolve ToolVersion
→ Validate Arguments
→ Evaluate Policy
→ Resolve Approval（如需要）
→ Resolve CredentialBinding
→ Resolve ToolBinding
→ Create ToolExecution
→ Execute Connector
→ Normalize/Redact Result
→ Finish ToolExecution
→ Write AuditEvent
```

#### ResolveApproval

```text
输入：Approval ID、Approver、Decision
输出：Approved/Rejected/Expired
关键规则：绑定原始 Principal、Tool、参数摘要和 Policy Version；只能消费一次
```

#### SearchTools

```text
输入：RequestContext、Query、Top-K
输出：有权限查看的 Tool Metadata
关键规则：先过滤权限再返回候选；完整 Schema 按需获取
```

### 5.3 诊断与治理

#### CheckUpstreamHealth

```text
输入：UpstreamService
输出：HealthStatus
关键规则：独立 Timeout/Concurrency；健康检查不泄露 Credential
```

#### QueryAuditEvents

```text
输入：Tenant、Actor、Tool、Trace、Time Range
输出：脱敏 AuditEvent
关键规则：不返回 Secret、完整 Token、完整敏感 Arguments
```

## 6. 限界上下文与状态所有权

| 限界上下文 | 拥有的核心状态 | 不拥有 |
|---|---|---|
| Registry | UpstreamService、Transport、Endpoint Metadata、Owner、Health | Tool Schema、Secret、Agent Session |
| OpenAPI Import | Source、ImportJob、ImportedOperation、NormalizedSchema、ReviewReport | Published Tool、Runtime Execution |
| Catalog | ToolDefinition、ToolVersion、Status、Visibility、Tags、SideEffect、SchemaDigest | HTTP URL Secret、执行结果 |
| Connectors | ToolBinding、HTTP/MCP Binding、参数/响应执行映射 | Tool 发布生命周期、Policy Decision、Secret Value |
| Identity | Tenant、AdminPrincipal、AgentServicePrincipal、Service Credential Mapping | 员工账号、员工会话、Egress Secret、Tool Schema |
| Policy | ToolPolicy、PolicyVersion、PolicyDecision | Secret Value、HTTP 执行 |
| Credentials | SecretReference、CredentialBinding、Grant Metadata | Secret 出现在 Tool Schema/Context/Audit |
| Approval | ApprovalRequest、Decision、Expiry、Consume State | Channel UI Session、长期 Agent Memory |
| Execution | ToolExecution、Idempotency、Outcome、Error Classification | Tool Catalog 生命周期、完整 Audit Payload |
| Audit | Append-only AuditEvent、Digest、Redaction Metadata | 业务授权决定、Secret、完整敏感 Payload |

## 7. Context Map 与依赖方向

### 7.1 Control Plane Context Map

```text
Registry
   ↓ Upstream Reference
OpenAPI Import
   ├──→ Catalog：提交 Draft Tool Candidate
   └──→ Connectors：提交 Draft ToolBinding

Catalog + Connectors
   ↓ Reviewed Snapshot
PublishTool
   ↓
Published ToolVersion + Published Binding + AuditEvent
```

### 7.2 Data Plane Context Map

```text
MCP Adapter
    ↓ RequestContext
Execution / CallTool
    ├──→ Catalog：解析 Published ToolVersion
    ├──→ Policy：获得 Decision
    ├──→ Approval：检查/创建 Approval
    ├──→ Credentials：解析 CredentialBinding
    ├──→ Connectors：解析 Binding 并执行
    └──→ Audit：追加事件
```

### 7.3 工程依赖方向

```text
MCP / Admin / CLI Interface
            ↓
Application Use Case
            ↓
Domain Model + Port
            ↑
Repository / HTTP / MCP / Secret Adapter
```

禁止：

- Domain import FastAPI、SQLAlchemy Request/Session 或 MCP SDK 类型；
- MCP Handler 直接查询 ORM；
- Catalog 直接发起 HTTP/MCP 请求；
- Connector 决定 Policy；
- Policy 读取 Secret Value；
- Credential Resolver 将 Secret 返回 Agent 层；
- Audit 反向决定是否允许执行；
- Demo 模块被 NexusMCP Core import；
- Shared 反向依赖具体业务上下文。

## 8. 三条核心业务链

### 8.1 OpenAPI 接入链

```text
Register Upstream
→ Submit OpenAPI Source
→ Security Validate / Parse / Normalize
→ Imported Operations
→ Draft ToolDefinition + Draft ToolBinding
→ Review Report
→ Review
→ Publish ToolVersion + Binding
→ Catalog 可见
→ Audit
```

### 8.2 Tool 发现链

```text
MCP tools/list / Tool Search
→ Protocol Adapter
→ Authenticate
→ RequestContext
→ Query Published Catalog
→ Visibility + Policy Filter
→ 返回当前 Principal 可见的 Tool Schema
```

### 8.3 Tool 调用链

```text
MCP tools/call
→ Protocol Adapter
→ Authenticate / RequestContext
→ Resolve ToolVersion
→ Validate Arguments
→ Policy Decision
   ├── DENY → Error + Audit
   ├── REQUIRE_APPROVAL → ApprovalRequest
   └── ALLOW
        ↓
Resolve CredentialBinding / SecretReference
        ↓
Resolve ToolBinding
        ↓
Create ToolExecution
        ↓
HTTP/MCP Executor
        ↓
Normalize / Redact
        ↓
Trace + Metric + Audit
        ↓
MCP Result / Error
```

## 9. 核心不变量

1. Import 只产生 Draft，不能自动 Publish。
2. Draft/Review Tool 不得出现在普通 `tools/list`，也不得被 `tools/call`。
3. Published ToolVersion 的 Schema/Binding 变更必须产生可追踪新版本或显式发布动作。
4. Tool 可见不等于允许调用；`tools/call` 必须重新执行解析和 Policy。
5. ToolBinding 必须绑定确定的 ToolVersion 和 Upstream。
6. ToolDefinition/ToolBinding/普通日志/Audit/RequestContext 中不得保存 Secret Value。
7. Inbound Credential 不得无条件透传为 Egress Credential。
8. Credential 解析只发生在 Policy 允许、执行即将发生的受控边界。
9. `REQUIRE_APPROVAL` 必须绑定原始 Principal、Tool、参数摘要和 Policy Version。
10. Approval 只能消费一次，过期、拒绝和参数变化必须重新决策。
11. Non-idempotent Tool 默认不自动重试。
12. Unknown Execution Outcome 不能当作普通失败再次执行。
13. Disabled Tool/Upstream 不可发现、不可调用，相关缓存必须失效。
14. Audit 使用 Append-only 语义，不保存完整敏感 Payload。
15. Modern 请求不依赖 Legacy Transport Session 保存业务状态。

## 10. Control Plane 与 Data Plane

### 10.1 Control Plane

负责低频配置和生命周期：

- Upstream 注册；
- OpenAPI Import；
- Draft/Review/Publish；
- Tool/Binding/Policy/Credential 配置；
- Tool Search 管理视图；
- Health 和版本查看。

### 10.2 Data Plane

负责高频请求：

- MCP 协议适配；
- Authentication 和 RequestContext；
- Tool Resolution；
- Policy/Credential/Approval；
- Connector Execution；
- Error Normalization；
- Trace/Metric/Audit。

### 10.3 共享模型原则

Control Plane 与 Data Plane 可以先部署在同一个进程，但共享相同 ToolDefinition/ToolVersion/ToolBinding 事实源，不分别定义两套模型。

## 11. 初步模块映射

以下是领域到 Python 模块的候选映射，不等同于立即创建全部目录：

| 领域边界 | 候选模块 |
|---|---|
| Registry | `modules.registry` |
| OpenAPI Import | `modules.openapi_import` |
| Tool Catalog | `modules.catalog` |
| Connectors | `modules.connectors` |
| Identity | `modules.identity` |
| Policy | `modules.policy` |
| Credentials | `modules.credentials` |
| Approval | `modules.approval` |
| Execution | `modules.execution` |
| Audit | `modules.audit` |
| MCP/Admin/CLI | `interfaces.*` |
| DB/HTTP/MCP/Secret/Otel Adapter | `infrastructure.*` 或所属模块的 Adapter |
| 应用组装和配置 | `bootstrap.*` |

模块建立规则：

- 先有真实 Use Case，再创建模块和文件；
- 不为目录对称创建空 Service/Repository/Schema；
- 第一层回答属于哪个业务，第二层回答承担什么职责；
- 跨模块协调由 Application Use Case 完成；
- 稳定跨域语义才能进入 Shared；
- 正式目录由 ADR-0001 冻结。

## 12. 当前已确认决策

1. Registry 当前正式登记 HTTP Upstream；Remote MCP Enum 只是 Deferred 扩展点。
2. ToolDefinition 由 Catalog 拥有；ToolBinding 由 Connectors 拥有。
3. 第一版可以单租户运行，但核心实体从一开始携带 `tenant_id`，测试行级隔离。
4. Control Plane/Data Plane 是代码和运行边界，不复制领域模型。
5. Modern MCP `2026-07-28` 为主线，Legacy 只做兼容。
6. MCP 动态 Gateway 使用官方 SDK v2 低层 `Server` Adapter。
7. OpenAPI Import 产生 Draft，Review 后才能 Publish。
8. Tool Catalog 保存对外契约，Connector 保存内部执行绑定。
9. Secret 通过 SecretReference 和 CredentialProvider 解析，不进入 Tool Schema。
10. 三个 Fake API 使用同一通用接入链，不增加场景专用核心代码。
11. PostgreSQL 是第一版唯一主业务数据库。
12. Tool 保存稳定身份，ToolVersion 保存不可变契约，ToolBinding 精确绑定 Version。
13. Publish ToolVersion + Binding 使用同一数据库事务；Audit 原子性后续决策。
14. 第一条 OpenAPI Import 只读取 Local Fixture，远程 URL Fetch 后置。

## 13. 后续待决策

以下问题不阻塞业务词汇冻结，但应在相关实现前形成 ADR 或实验结论：

1. Data Plane Published Snapshot/Cache 的实现方式。
2. Policy Condition 的最小表达能力和冲突优先级。
3. 开发环境 SecretProvider 使用环境变量还是本地文件 Store。
4. Audit 同步/异步写入及与 Publish 的原子性。
5. Remote MCP 是否重新进入主线；只有 ADR-0017 触发条件满足后才讨论版本和名称冲突策略。
6. 远程 OpenAPI URL Fetch/SSRF 的完整策略。

## 14. 概念学习附录

### 14.1 OpenApiImportJob 与 ImportedOperation

二者是“任务与产出”的关系：

```text
OpenApiImportJob
├── ImportedOperation: GET /employees/{id}
├── ImportedOperation: GET /employees
└── ImportedOperation: POST /employees
```

OpenApiImportJob 不只是调用 Parser，它覆盖：

```text
接收 Source
→ 安全读取
→ 版本与文档校验
→ 解析 servers/paths/security/schema
→ 展开或标准化 $ref
→ 生成 ImportedOperations
→ 检测冲突和不支持特性
→ 生成 Draft Tool/Binding Candidate
→ 输出 Review Report
```

ImportedOperation 是一个 API Operation 的标准化中间表示，例如：

```text
operation_id: getEmployee
method: GET
path: /employees/{employee_id}
path_parameters: employee_id:string|required
query_parameters: []
request_body: null
security_requirements: service_token
normalized_schema: {...}
```

它还不是 Published Tool。只有经过 Draft、Review、Publish 后，才进入 Tool Catalog。

### 14.2 SecretReference 与 CredentialBinding

SecretReference 是 Secret 的位置引用，不是真实 Secret：

```text
provider: environment
locator: OPS_SERVICE_TOKEN
```

或者未来：

```text
provider: vault
locator: kv/nexusmcp/operations/service-token
```

数据库保存 `provider + locator`，真实值保存在环境变量、Vault、Cloud Secret Manager 等受控系统。

CredentialBinding 回答：

```text
当前 Agent Service Principal（或 Tenant 默认）
+ 当前 Tool
+ 当前 Upstream
→ 应选择哪个 SecretReference
```

运行时：

```text
Policy ALLOW
→ CredentialBinding
→ SecretReference
→ CredentialProvider
→ Secret Value
→ 注入上游请求
```

Secret Value 只能短暂存在于受控执行边界，不返回 Agent，不写普通日志和 Audit。

### 14.3 Tool Catalog 与 ToolBinding

Tool Catalog 可以理解为企业内部的“工具目录/能力目录”。它保存 Agent 能看到的契约：

```text
directory.get_employee
- description
- input schema
- output schema
- version
- owner/tags/namespace
- status/visibility/side_effect
```

ToolBinding 保存内部执行方式：

```text
directory.get_employee@v1
→ executor_type: http
→ upstream: employee-directory
→ GET /employees/{employee_id}
→ employee_id 放入 Path
```

类比：

```text
ToolDefinition ≈ Interface / 对外契约
ToolBinding    ≈ Interface 到实现的绑定
Connector      ≈ 具体 Adapter
```

同一个 ToolDefinition 可以在不同环境绑定不同 Endpoint，而 Agent 契约不变。

### 14.4 Registry 与 Tool Catalog

| Registry | Tool Catalog |
|---|---|
| 登记上游系统 | 登记对 Agent 暴露的 Tool |
| Employee Directory API | `directory.get_employee` |
| Operations MCP Server | `ops.get_service_status` |
| 关注 Endpoint、Transport、Owner、Health | 关注 Schema、Version、Status、Visibility |

一个 Upstream 可以产生多个 Tool；多个 Tool 也可以由同一个 Upstream 执行。

### 14.5 Agent Service Principal 与 Credential

| 概念 | 回答的问题 |
|---|---|
| Agent Service Principal | 哪个 Agent 服务正在调用 NexusMCP？ |
| Inbound Credential | Client 如何向 NexusMCP 证明身份？ |
| Egress Credential | NexusMCP 使用什么访问 Upstream？ |
| CredentialBinding | 当前调用应选择哪个 Egress Credential？ |

独立部署可以使用固定 `static_service` Principal；多个 Agent 共用时，统一由 `AgentServiceAuthenticator`
把机器 Credential 映射为不同 Service Principal。具体企业认证方式属于可替换 Adapter，不进入 Core 模式。
员工身份停留在 Agent 服务或原业务系统，不进入 NexusMCP Principal、Policy 或 Audit。

### 14.6 Draft、Review、Publish 与 Disable

```text
ImportedOperation
→ Draft Tool
→ Review
→ Published ToolVersion
→ Disabled（如需要）
```

- Draft：系统生成或人工编辑，普通 Agent 不可见；
- Review：检查名称、Schema、Auth、SideEffect、风险和不支持特性；
- Published：成为稳定对外契约，可被发现和调用；
- Disabled：停止发现和调用，但保留历史版本与 Audit。

### 14.7 Use Case、Domain、Port 与 Adapter

```text
Use Case
= 完成一个用户/系统目标的业务编排

Domain Model
= 状态、业务规则和不变量

Port
= Domain/Application 对外部能力提出的接口需求

Adapter
= 数据库、HTTP、MCP、Secret Store 对 Port 的具体实现
```

例如：

```text
CallTool Use Case
→ ToolCatalogPort
→ PolicyEvaluatorPort
→ CredentialProviderPort
→ ToolExecutorPort
→ AuditSinkPort
```

PostgreSQL、HTTPX、Vault 等外部实现是 Port 的 Adapter，不应反向决定 CallTool 的业务流程；Remote MCP
SDK 只有 ADR-0017 触发后才可能成为 Future Adapter。

### 14.8 Bounded Context、Module 与 Microservice

- Bounded Context：一个业务语言和状态所有权边界；
- Python Module：承载边界的工程组织方式；
- Microservice：部署、扩缩容和故障隔离单元。

三者不是同义词。NexusMCP 第一版使用模块化单体：多个 Bounded Context 可以位于同一进程，但必须维持清晰依赖和状态所有权。

### 14.9 Entity、Value Object 与 Aggregate

- Entity：通过 Identity 持续存在并变化，例如 ToolDefinition、OpenApiImportJob；
- Value Object：由值本身定义、通常不可变，例如 SchemaDigest、SecretReference；
- Aggregate：需要在一个一致性边界内维护不变量的一组对象；
- Aggregate Root：外部修改该 Aggregate 的唯一入口。

本文先冻结语言与状态所有权，不提前断言所有对象的 Aggregate 关系。Aggregate 应结合事务、一致性和数据规模确定，而不是为了套 DDD 名词创建复杂对象。
